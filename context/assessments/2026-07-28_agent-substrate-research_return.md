## §2 The prior-art map + the defensible novelty claim (Charge 3, incl. the thesis §4 leads)

Complementarity note: the 2026-06-23 prior-art return covered the *platform* ancestry (HA, openHAB, SmartThings, Hubitat, HomeKit/Matter, Node-RED, event-sourcing/CQRS, local-first). This section covers the *enforcement* ancestry the north star does not cite. No overlap conflict found.

### 2.1 The ancestors, established at source

**Industrial functional safety (IEC 61508/61511) — the enforcement primitive is ~40 years old and standardized.** The Safety Instrumented Systems discipline IS deterministic, unbypassable enforcement at a physical boundary: "SISs take the process to a safe state when predetermined conditions are violated"; independence is doctrinal — "Ideally such protection layers should be independent from one another so that any one will perform its function regardless of the action or failure of any other protection layer… Ideally, SISs and the BPCS should be independent" (Primatech IEC 61511/S84 FAQ). Hardware enforcement predates software: Pilz "In 1987 Pilz patented the first emergency stop relay to protect man and machine"; SIL-3 safety PLCs (Siemens F-CPUs, TÜV-certified) are commodity. What SIS does NOT have: hash-chained tamper evidence, event-sourced total ordering, replay, AI-agent adjudication, or commodity home deployment — SIS engineering is bespoke and expensive.

**Runtime assurance / runtime verification — deterministic guarding of untrusted controllers is an established field with an ASTM standard.** Simplex (Sha 2001): "The DM monitors the state of the system and switches control from the advanced controller (AC) to the BC if using the former could result in a safety violation." ASTM F3269-21 standardizes RTA for aircraft functions with "non-deterministic behavior." RL shielding (Alshiekh et al., AAAI 2018): "The shield monitors the actions from the learner and corrects them only if the chosen action causes a violation of the specification" — model-agnostic, action-level adjudication of a learning agent; the direct academic ancestor of adjudicating an AI agent at the boundary. NASA Copilot/R2U2 are flying runtime monitors. None target homes; none integrate tamper-evident logs or replay as first-class.

**Capability security — the concept is 1966; the verified kernel is real; home actuation application is not.** Dennis & Van Horn 1966 defines capabilities; seL4 is "unique because of its comprehensive formal verification," and the HACMS red-team record is real: "The formal method-generated code foiled all Red Team attempts… To this day, the system has yet to be successfully hacked" (DARPA). Kry10 confirmed as a commercial seL4 vehicle targeting cyber-physical devices ("A secure OS for software defined machines… mission critical connected devices"; "Trust but Isolate®"); Proofcraft confirmed (verification services). IoT capability tokens exist in research (CAPLets, SEC 2021). No deployed capability-security system specifically governing home/building actuation with AI-agent adjudication was found.

**CHERI/Morello + the claimed commercial parts — both parts EXIST; status is early.** SCI Semiconductor ICENI: "world's first commercial CHERI implementation in silicon" — first silicon + Early Access Programme ("selected customers and partners early access to silicon devices"), GlobalFoundries fab; not evidenced as high-volume shipping. Codasip X730: "the first commercially licensable processor implementing CHERI-RISC-V," listed available now — licensable IP, not shipped end silicon. The adoption-deadlock characterization is supportable (DARPA funding since 2010 + ~£350M UK DSbD 2019–2025 → one licensable core and one early-access MCU family by mid-2026), but state it as "slow ecosystem adoption," not "failed" — first commercial silicon now exists. Thesis §4.1 [PROVEN technically; CONTESTED commercially] **holds**.

**Total ordering applied to control — determinism at the boundary is ubiquitous; the event-sourced composition is not.** PLC scan-cycle determinism (IEC 61131-3) and ARINC 653 time partitioning solve deterministic execution at the physical boundary. Process historians (AVEVA/OSIsoft PI) provide audit *trails* for 21 CFR Part 11-style compliance — access-controlled change logs, **not cryptographic tamper evidence**. No event-sourced, hash-chained, deterministically-replayable SCADA or building-automation product was found.

**Tamper-evident logging — a 25+-year-old textbook primitive.** Schneier & Kelsey 1999 (logs "impossible to undetectably modify or destroy" post-compromise); Crosby & Wallach 2009; Certificate Transparency RFC 6962 ("The append-only property of each log is technically achieved using Merkle Trees"). The primitive must never be claimed as novel.

**The closest smart-home compositions — all partial, all pre-LLM-agent, none tamper-evident.** ProvThings (NDSS 2018): IoT provenance graphs on SmartThings — forensic, no crypto tamper evidence, no prevention. IoTGuard (NDSS 2019): "dynamic, policy-based enforcement system for IoT… directly blocks unsafe and undesired states" — but enforcement rides *cooperative app instrumentation* ("the app transmits its information… to IOTGUARD before it executes actions"), hence bypassable by any non-instrumented path; no tamper-evident log, no total ordering, no replay. ContexIoT (NDSS 2017): contextual permission *prompts* — human-in-the-loop. Soteria/IoTSan/ExPat: design-time model checking. These are the ancestors the north star should cite by name — the pattern across all of them (bypassable hooks, no integrity, no ordering, no deployment longevity) is precisely the delta the composition closes.

### 2.3 The defensible novelty claim (public-writing grade — the thesis's prediction CONFIRMED: it is the composition)

**Claimable:** "Every ingredient here is deliberately old: independent safety layers are how industry has guarded machinery since the safety relay (1987) and IEC 61511; runtime-assurance switches are an ASTM aviation standard; hash-chained logs date to Schneier and Kelsey (1999); event sourcing and replay are textbook enterprise patterns. What did not previously exist is their composition at one point: a single, unbypassable actuation gateway for AI agents in ordinary homes that adjudicates every command deterministically, records it in a totally ordered tamper-evident log, and can replay any decision bit-for-bit — on hardware you can buy for the price of a dinner." *(Language-law check: this claims a missing composition, not superiority over model-based judgment — passes. Honesty-table check: until chain_hash computation and the agent seams land (§5), the public tense for the tamper-evidence and agent-adjudication clauses is "designed for," not "does.")*

**Must NOT be claimed** (each refutable in one citation): novelty of (a) deterministic/unbypassable enforcement at a physical boundary (SIS, safety relays); (b) runtime guarding of untrusted or learning controllers (Simplex 2001, ASTM F3269, shielding 2018); (c) tamper-evident logging (1999) or Merkle/append-only logs (RFC 6962); (d) deterministic replay or total ordering as techniques; (e) policy enforcement or provenance logging for smart homes as such (IoTGuard, ContexIoT, ProvThings); (f) runtime enforcement for LLM agents as such (AgentSpec, RoboGuard).

- **Samsung SmartThings/Bixby** (2026 "AI Home", ~300M devices): newsroom material contains "no language addressing safety measures, user permissions, confirmation protocols, audit trails, or operational limits."
- **Home Assistant**: philosophy is explicitly tool-not-substrate ("AI as a powerful *tool*… as opposed to something that takes over your home"); enforcement = coarse entity-exposure lists ("exclude it from mission-critical things"); AI Task entities are opt-in data generation. No policy language, no audit.
- **Homey**: ChatGPT integration can "check device status, control devices, start Flows" with no published restrictions or confirmations.

### 3.3 The FOSS race-condition sweep (thesis falsifier #6) — the closest three, with distance

1. **Home Assistant** — closest by ecosystem, farthest by intent. Granular permissions/RBAC: open request since 2020, community verdict "unlikely to happen any time soon." The first-ever audit-log architecture proposal (**"Minimal Security Audit Log," opened 2026-02-24**) explicitly scopes to login events only — "This proposal does **not** aim to: Introduce RBAC or permission model changes" — and sat at **zero maintainer replies** at check. Recorder DB is mutable SQLite. Distance: would still need per-actor permissions, an ordered immutable command log, tamper evidence, and agent adjudication — i.e., the architecture, not a feature. **Verdict: dormant on audit/governance, active on AI features.**
2. **ioBroker** — has object-level ACLs (the *skeleton* of multi-tenancy) and a hobby AI-assistant adapter; no audit log, no ordering, no tamper evidence, no agent policy.
3. **openHAB** — RBAC is an open core issue (openhab-core #3305); single-trust-domain by design; no audit or LLM-governance work found. Farthest of the three.

No event-sourced FOSS smart-home project with an immutable-log/total-ordering story was found (search trail in §6). **Falsifier #6 status: DORMANT but not dead** — HA is the only project with the network effects to close the gap quickly, and its current posture is explicitly minimal; the standing quarterly watch (tripwire T6 class) is the right instrument, now with named watchables: the HA architecture discussion #1346 thread and any HA blog move from exposure-control to permissions/audit.

### 3.4 Academic — one genuine claim-jumper

**HearthNet (Imperial College London, arXiv 2604.09618, Mar 2026) is the single closest thing to a policy kernel for the home found anywhere in this sweep:** "policy-bound actuation leases in which the root agent issues short-lived, machine-checkable authorizations binding each state-changing command to an identity, device scope, parameter envelope"; a "librarian-as-observer pattern… mirrors coordination traffic into a versioned repository, providing crash recovery, attribution, and full auditability"; Git-backed state with base-commit verification to reject stale commands; real hardware (Hue, JBL, Reolink, LG). Distance: prototype not product; enforcement trusts the root agent (no independent unbypassable chokepoint); Git integrity is not a hardened tamper-evident log; no replay-deterministic projection; no multi-occupant longitudinal deployment. **Significance: independent invention of the core moves — the strongest evidence that the design space is being discovered now, and the strongest argument that the positioning window should not be assumed open past 2026.** Others: SAGE (Samsung, real devices, no governance), Sasha (no governance), SimuHome/SMH-Bench (benchmarks), AgentGov-SC (governance-as-analysis, "no implementation evaluation has been conducted"). The SmartThings-security lineage (ContexIoT/IoTGuard) has no active 2024–26 successor with real deployment — it migrated into benchmark literature.

### 8.4 The instruction-vs-evidence datapoint (ADDENDUM 2's four owed items)

**(1) Has anyone already said it? Verdict: ANCESTORS-EXIST-BUT-FORM-UNSTATED — with two 2026 near-misses that make priority a matter of months.** The ancestors, honestly mapped: the end-to-end argument (Saltzer/Reed/Clark) is about *placement* of verification relative to the channel, where the claim is about *independence* of verification from the actor — ancestor, not statement. IETF RATS (RFC 9334) supplies the cleanest existing vocabulary ("Evidence: A set of Claims generated by an Attester to be appraised by a Verifier") but is about platform identity, not actuation outcomes, and says nothing about model progress. IEC 61511's independent-protection-layers doctrine institutionalized "the controller cannot be its own witness" decades ago — framed as failure-independence, not as an asymmetry under capability growth. Runtime verification observes-not-instructs but never claims observation survives capability progress while instruction does not. The two near-misses: **Salfeld-Nebgen, "Governing Actions, Not Agents" (arXiv 2606.26298, June 2026)** — "When an action is locally well-formed… but its correctness depends on a fact about the world… alignment, runtime behavioural monitoring, and sandboxing cannot adjudicate it, because that fact is absent from the execution context" — states the *structural* half almost exactly; and **AAIF's cMCP post (2026-07-29)** — "can a party who does not trust the operator still verify what actually happened?" — states the *trust-boundary* half and ships TEE-signed per-call evidence. **Neither states the diachronic half — that model progress absorbs instruction but cannot absorb evidence; that instruction is a substitutable input to a reasoner while evidence is a non-substitutable output of an observer.** That form appears genuinely unclaimed as of 2026-07-31. Disposition: we can still claim the formulation, but the June and July 2026 items show convergence — if the formulation is worth planting publicly, it is worth planting in the first post-gate content window, and both near-misses must be cited as the adjacent statements they are.

**(2) Does it survive contact? Refutation attempt: FAILED — the distinction survives.** The strongest counter ("a sufficiently instrumented model-plus-tooling stack makes a separate witness redundant") was tested against what platforms actually ship, per the brief's never-against-announcements rule: the MCP spec changelog (2025-11-25) contains structured output, OAuth hardening, tasks — **no signed tool results, receipts, or attestation of any kind**; OpenAI ships tracing (observability), not verified execution receipts; Google A2A signs **AgentCards (identity), not task results**; Fetch.ai's AEVS beta ships "tamper-evident, ECDSA-signed receipts for every AI agent tool execution" — but the *agent signs its own report*, and the site itself concedes it "does not record… what the API returned"; Microsoft's Verifiable Compliance Receipts is a draft in which the agent process signs both pre- and post-execution with its own key — self-attestation, not witnessing; Langfuse/LangSmith audit logs cover platform admin actions on mutable backends. **The honest complication is Matter itself:** the interaction model provides real device-side confirmation ("Invoke Response… command responses and statuses for each invoke request" + subscription-based reporting of actual state) — a witness *statement*, from the device, which is more than the agent's say-so. But it is confined to the fabric's session security, is not portably signed, and terminates in a controller log with no integrity guarantee: **a witness statement with no chain of custody.** That is precisely the seam this substrate occupies — turning the fabric-local witness statement into a totally-ordered, attributable, (once H3 lands) tamper-evident record. The refutation fails; the distinction stands *on today's shipping evidence*.

**(3) F-1 watch definition.** Sources a standing watch monitors (platform axis, never benchmark scores): the MCP spec changelog + SEP stream (modelcontextprotocol.io/specification/*/changelog; github.com/modelcontextprotocol — SEPs mentioning signature/attestation/receipt/provenance on *tool results*) · OpenAI platform changelog (platform.openai.com/docs/changelog) · the A2A spec repo (github.com/a2aproject/A2A — watch for signing extended from AgentCard to Task/Artifact objects) · Matter spec releases (csa-iot.org) · two leading indicators whose status *flip* from draft/beta to shipped-default is the early warning: cMCP (github.com/agentrust-io/cmcp) and Microsoft's Verifiable Compliance Receipts proposal. **Recognition rule:** the falsifier is a shipped, default-path mechanism in which the signature over an action's result is rooted **outside the agent stack** — the tool server, device, or counterparty signs what happened, such that a third party trusting neither the model nor its operator can verify the external state change. Anything where the actor signs its own report — however cryptographically dressed, including hash-chained self-logs and agent-keyed receipts — is a tool-use-reliability improvement, not F-1.
