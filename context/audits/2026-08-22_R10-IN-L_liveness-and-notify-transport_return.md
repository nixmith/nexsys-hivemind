# R10-IN-L — the liveness contract + the notify transport

## §0 The two recommendations, in one paragraph

**R-L1 = C-1** and **R-L2 = T-0**, with **R-L3 = NO**. `/health` as R-9 designs it is a *readiness* bit (the projection is LIVE), it is the correct gate for `systemctl start`, and the evidence does not carry a second endpoint yet: document the promise precisely, keep the composite in `SystemHealthSnapshot` only, and treat `/readyz` as the *gated successor* whose trigger is the arrival of any external prober. On the transport: the M5-D adjudication survives re-pricing but its live variable has collapsed — FFM is final in JDK 22 while **LTD-01 forbids preview features in production code** (`HomeSynapse_Core_Locked_Decisions.md:50`), so T-2 is not a transport decision at all but an LTD-01 amendment that already has a larger independent driver (JEP 491, named in LTD-01's own reversal criteria `:71`); T-1 buys a one-shot `READY=1` that `ExecStartPost` already delivers, at the price of loosening `NotifyAccess=` to `all` on a deliberately hardened unit; T-4 is dominated by T-1 in every column. So: **stay on `Type=exec` + the probe, defer M13 indefinitely** — and *rewrite the staged M13 flip block*, because at `89a912e` its "two-line edit" framing is false in a way that produces a start-limited DOWN unit (§3, T-0/f1). Three findings outrank the options and are filed as charter items regardless of the words: **(1)** the system's one designed liveness signal — C12-03's `WATCHDOG=1` — is emitted into `NoOpHealthReporter` on every host, so it is *unobserved everywhere today*; **(2)** `/health` **does not exist in code** at `89a912e` (R-9 is ISSUE-READY, not landed), so the charter is ruling on an authored contract; **(3)** an unauthenticated `/health` **departs from a resolved Locked-doc open question** (Doc 09 §15 Q1, `09-rest-api.md:997–:998`: *"No unauthenticated endpoint is needed"*) — that fold is owed under **every** C-option, C-1 included.

## §3 The transport options, re-priced against today's facts

Two primary facts changed the pricing since 2026-06-07, and one did not:

- **`NotifyAccess=` defaults to `none`, and is *implicitly set to `main`* when `Type=notify`/`Type=notify-reload` or `WatchdogSec=` is used** — *"If those options are used but NotifyAccess= is not configured, it will be implicitly set to main."* (`systemd.service(5)`). `main` accepts *"only service updates sent from the main process"*; `exec` extends to *"any of the main or control processes originating from one of the Exec\*= commands"*; `all` to *"all members of the service's control group"*.
- **FFM is final in JDK 22** (`java.lang.foreign`, Java SE 22 API docs: *Since: 22*, no PREVIEW marker; JEP 442 is the third preview, JDK 21) — and **LTD-01 `:50` reads *"No preview features permitted in production code."*** So `--enable-preview` on 21 is not a cost to price; it is *forbidden*.
- **Unchanged:** `DatagramChannel.open(ProtocolFamily)` in Java SE 21 carries the API Note *"Unix domain sockets are not supported."* — the M5-A finding, now cited to the JDK's own API doc rather than to a coder pushback.

**f1 — the staged flip block is a live trap, not an inert comment.** Unit `:100–:106` tells the next reader that enabling `Type=notify` + `NotifyAccess=main` + `WatchdogSec=60` + `Restart=on-watchdog` is *"a two-line edit, not a redesign."* At `89a912e` that is false in two independent ways. (a) `Type=notify` makes systemd set `$NOTIFY_SOCKET`; `selectHealthReporter` (`:1476–:1489`) then constructs `SystemdHealthReporter`, whose `UnixDatagramTransport` ctor throws `IllegalStateException` (`SystemdHealthReporter.java:158–:166`), which the **catch at `:1483` swallows into `NoOpHealthReporter`** — "so a systemd host does not crash the boot." Under `Type=exec` that fallback is correct; under `Type=notify` it means **`READY=1` is never sent**, systemd holds the unit *activating* until `TimeoutStartSec=120` (`:55`), fails it, `Restart=on-failure` fires, and `StartLimitBurst=5/300 s` lands the unit **start-limited DOWN in roughly ten minutes**. (b) Independently, `WatchdogSec=60` with a NoOp reporter means no `WATCHDOG=1` ever arrives → *"the service is placed in a failed state and it will be terminated with SIGABRT"* (`systemd.service(5)`) at 60 s. **Recommendation regardless of the transport word:** replace `:100–:106` with a DANGER-annotated block naming the transport as the precondition, or delete it and keep the pointer in `boot-contract-map.md:77–:82`. This is a `passes-but-false` line in the unit's own documentation and it costs one comment hunk to close.

**f2 — T-0's instrument is blind to the class the watchdog exists for.** An HTTP GET on `/health` answered from an `AtomicReference` read proves *the HTTP path is alive*. The hang class C12-03 was written for — carrier-pool exhaustion, which **LTD-01 `:71` names by mechanism** (sqlite-jdbc's `synchronized native` methods pinning carriers; JEP 491 in Java 25 removes only the monitor half) — would stall `HealthLoop`'s virtual thread (`:93`) — while an HTTP request served from a *platform* thread would keep answering 200. **`WATCHDOG=1` catches that class by construction; a `/health` timer catches it only if Javalin 6.7.0's request threads are themselves virtual — which this lane did NOT verify (no bytecode read was performed on the pinned jar; flagged as the first thing a T-0 spike must settle).** T-0 is therefore not a substitute for the watchdog: it covers a *different* class (a wedged projection, a surface that died without the process dying). The charter should not buy T-0 believing it is C12-03.

**f3 — T-0's restart storm.** A timer-driven `systemctl restart homesynapse.service` counts against `StartLimitBurst=5`/`StartLimitIntervalSec=300` like any other start, so K·N must be budgeted against 300 s or the watchdog *causes* the start-limited DOWN it exists to prevent. Two more T-0 costs the brief did not name: the checker unit must run **as root** to restart the service (a new privileged unit on a host whose service unit is deliberately least-privilege, `:68–:93`), and `systemd.timer(5)`'s **`AccuracySec=` defaults to 1 min**, so a 15 s period is meaningless unless `AccuracySec=1s` is set explicitly.

**f4 — T-1 requires `NotifyAccess=all`, and the ExecStartPost shortcut is structurally impossible.** A JVM-spawned `systemd-notify` child is neither the main process nor *"a control process originating from one of the Exec\*= commands"*, so both `main` (the implicit default under `Type=notify`) and `exec` reject it; only `all` accepts it. And the tempting zero-Java variant — `ExecStartPost=/usr/bin/systemd-notify --ready` — cannot work: under `Type=notify`, `ExecStartPost=` runs only **after** `READY=1` has been received, so it can never be the thing that sends it. **f5:** even with `all`, `systemd-notify(1)` warns that *"if an auxiliary process of the unit sends an sd_notify() message and immediately exits, the service manager might not be able to properly attribute the message to the unit, and thus will ignore it, even if NotifyAccess=all is set"* — the recommended mitigation is `--pid=`, which *"will only succeed when invoked with sufficient privileges"* and otherwise silently falls back to its own PID. Under `User=homesynapse` + `NoNewPrivileges=yes` (`:24`,`:69`), assume the fallback. **f6:** the *entire* benefit is replacing an `ExecStartPost` probe that already works, on a unit whose hardening block would have to be loosened to get it.

**T-2, priced honestly.** Once the pin moves, T-2 is the best transport by every column: zero deps, in-process, correct `$MAINPID` attribution, negligible Pi cost, and it drops in behind a seam that already exists (`NotifyTransport`, `:137–:143`) so the blast radius is one private class. But **the pin is not this decision's to move**: LTD-01 is a Locked decision with its own §18 amendment path, its reversal criteria are performance-shaped, and JEP 491 (named at `:71`) is a far larger reason to consider 21→25 than sd_notify is. Corretto 25 (LTS) went GA **2025-09-17**, supported **through October 2032** — so the *availability* half of the M5-D decision tree is now satisfied; only the *governance* half is open. **Price it as a charter item on the JDK-trajectory docket, and let the transport ride it, never drive it.**

**T-3.** The M5-D rejection **HOLDS and strengthens**: it was dominated in 2026-06 by "a catalog dependency + the worst native-image fit for a three-syscall job"; it is more dominated now, because the zero-dep in-process alternative it lost to is *final* rather than *preview*. Nothing in T-3's cost row moved in its favour.

**T-4.** Both shapes are dominated by T-1. A one-shot helper binary sends from a child PID — the identical `NotifyAccess=all` + attribution-race problem as T-1 — while adding a C toolchain and a shipped native binary to the trust surface, to avoid depending on a `systemd-notify` that is present on every systemd host by construction. The persistent sidecar adds a second process whose own liveness nothing supervises, and still sends from its own PID. The arm64 CI leg being real (`install-smoke.yml:40–:46`, `ubuntu-24.04-arm` — native, so no cross-compile is even required) lowers T-4's *build* cost without touching the reason it loses.

## §4 The coupling with R-9's `/health` (the 3×5)

What each transport option needs `/health` to *promise*. **L** = must mean liveness; **R** = readiness is fine; **—** = does not use it.

**The walk that makes the coupling load-bearing (T-0 × C-1).** `/health` returns 503 for every non-LIVE mode, and REPLAY is a *legitimate* mode on a cold boot with a large event store. A timer that restarts after K consecutive non-200s therefore kills a hub that is correctly replaying, which restarts the replay, which never completes: **an unbounded loop caused by the watchdog, not the fault.** The existing `--timeout 90` gate (`unit:50`) already encodes an assumption that replay finishes inside 90 s, so the window is not wide today — but a start *failure* is bounded by `StartLimitBurst` while this loop is a restart *cause*, and the two interact (f3). **Conclusion: `T-0`'s timer requires `C-3`. The one-word answers are coupled, and the charter should not split them.** Since I recommend the timer be *authored and held* rather than shipped (§5), C-1 stands today and C-3 becomes owed the moment the timer does.

## §5 The recommendation + the one-word asks

**R-L1 — the contract. Recommend C-1** (≤10 lines): the composite has no honest definition today — `aggregatedHealth` is a hard-coded constant (`:836`), `integrationCount` is a hard-coded zero (`:840`), there are no `HealthContributor` impls, and "bus progress" cannot be distinguished from a quiet house without an expected-rate model nothing owns. C-2 re-creates OR-E3-PROBE's availability class from the far end. C-3 is *right* but premature: it buys a `/livez` whose only consumer would be a prober we are not shipping, and it doubles the surface R-9 has not yet landed. So: ship R-9 as designed, **name it readiness in every doc it touches** (the word `/health` is the misnomer; the promise is what matters), keep the composite in `SystemHealthSnapshot` and on the FE's reserved B2 route, and carry C-3 as a *gated successor* with a written trigger. Owed either way: the Doc 09 §15 fold (§2).

**R-L2 — the transport. Recommend T-0 (STAY), with the watchdog timer AUTHORED-AND-HELD, not shipped** (≤10 lines): every transport that would flip `Type=notify` buys, at v1, a `READY=1` that `ExecStartPost` already delivers correctly — at the price of loosening `NotifyAccess=` to `all` (T-1/T-4) or amending LTD-01 (T-2/T-3). ## Harvest (≤5)

1. **A fallback that is correct under one `Type=` is a trap under another.** `selectHealthReporter`'s catch-all degrade to NoOp is right for `Type=exec` and produces a start-limited DOWN unit under `Type=notify` — the same three lines, opposite verdicts. Any "staged flip" comment must name the code precondition, not just the unit edit.
2. **Name the promise, not the path.** `/health` that means *readiness* will be probed as *liveness* by the first tool that meets it. The misnomer costs nothing until an external prober exists, and then it costs a restart loop.
3. **A watchdog is only as good as the thread its beat rides.** `WATCHDOG=1` from the health loop's virtual thread catches carrier-pool exhaustion; an HTTP probe answered by a platform thread cannot. Pick the instrument from the failure class, never from convenience.
4. **The Locked register can settle a "cost" row outright.** LTD-01's *"No preview features permitted in production code"* removes `--enable-preview` from the FFM matrix entirely — a decision matrix that prices what a Locked decision forbids is doing arithmetic in a closed room.
5. **Cite the LTD you mean.** The JDK pin is **LTD-01** (Java 21 LTS), not LTD-10 (Gradle/Kotlin DSL) — the brief and `install-smoke.yml:56` both attribute it to LTD-10. A one-word fix in each, but the charter is about to reason over "the pin".
