## Phase B — the fix (pre-authorized ONLY for the confirmed label-wipe mechanism): LC-LABEL-LOG

Replace the direct-mutation labeling in the affected ITs with **label-through-the-log**, using the production apply path end-to-end:

- Read the entity's CURRENT record (post-barrier), apply the label to a copy, and **publish an idempotent F1 `entity_registered` re-emit** carrying the labeled record (publish-first — the fact is durable in the log before delivery, per REG-INV-1's write-ahead clause), using the event-model mirror family exactly as production re-emits do.
- **Await the projection applying it:** extend/reuse the DURc barrier helper so the await targets the checkpoint reaching **this re-emit's own log position** (the type-filtered-checkpoint lesson: the target is the last MATCHING event's position, never log head).
- **Why this retires the class instead of re-mitigating it:** every registry mutation now rides the single ordered apply path — any adoption-time or re-emit delivery sequences BEFORE the label fact by log order, so nothing can wipe the label afterward *by construction*. That is REG-INV-1's own discipline applied to the tests (the production ArchUnit rule `REGISTRY_MUTATION_ONLY_VIA_PROJECTION` never covered tests; this WU makes the tests obey it voluntarily).
- Apply to **every G-2-censused label site** (expected: the three DURc ITs) as independently revertible hunks. The DURc barrier calls may then be redundant at the label seam — LEAVE THEM (they still guard the adoption→first-assert window); note redundancy as [INFO] if observed.

## What to Watch Out For

- **Tests must inject `Clock`.** Do NOT use `Clock.systemUTC()`, `Instant.now()`, `System.nanoTime()`, or `System.currentTimeMillis()` in this module's test code. Use `Clock.fixed(Instant.parse("2026-01-01T00:00:00Z"), ZoneOffset.UTC)` injected via constructor/`@BeforeEach`. **Enforcement reach:** `NO_DIRECT_TIME_ACCESS` runs from `com.homesynapse.app`'s test classpath, so it mechanically catches PRODUCTION code in every non-whitelisted module (plus app's own tests) — it does **not** scan this module's test source set. Clock-injection here is a self-enforced project convention that PM review, not `./gradlew check`, enforces.
- **The type-filtered checkpoint is not a log-head cursor** (the DURc coder-lesson, banked at cost): the bus advances a filtered subscriber's checkpoint ONLY on filter-matching deliveries; barrier targets must be a MATCHING event's position or they deadlock deterministically.
- **Publish-first ordering:** the re-emit must be durable-in-log before you await its application; read the position from the publish result, never re-derive by scanning.
- **The re-emit carries the FULL record:** idempotent-by-identity upsert REPLACES on different state — a partial record wipes what it omits (the exact defect class you are fixing; do not reproduce it in the fix).
- **`-XX:ActiveProcessorCount` shapes JVM defaults** (common pool, GC threads) — it is the repro instrument, not a config to ship; assert it appears nowhere in the final tree.
