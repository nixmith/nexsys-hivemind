## §1 What this implements
The drift and its exhibits are AMD-101 §1 (`homesynapse-core-docs/design/amendments/AMD-101_…`); the ruling is `nexsys-hivemind/context/planning/2026-09-12_v71_BUSFIX-b_ruling-of-record.md`. In one sentence: the LIVE loop stops delivering the positions it is handed and starts delivering what the store holds beyond its cursor, in order; the notification only wakes it.

The existing pieces this reuses: `ReplayDriver` already pages with `eventStore.readFrom(pageAfter, MAX_REPLAY_PAGE)` and checkpoints per delivery (`ReplayDriver:141`, `:167`, `:202`) — the LIVE loop adopts the same discipline; `SubscriberSupervisor.deliver` keeps every result semantic (SUCCESS · PARKED with a DLQ row · CIRCUIT_BREAKER_TRIPPED and INFRASTRUCTURE_FAILURE → SUSPENDED); `TransitionCoordinator.drainAndPromote` (`:109–:190`) keeps the `onCaughtUp` single-shot (AMD-42 §3.4.3) and the mode CAS under the queue lock.

## §5 What to watch out for
- The paste-block of record: **Tests must inject `Clock`.** Do NOT use `Clock.systemUTC()`, `Instant.now()`, `System.nanoTime()`, or `System.currentTimeMillis()` in this module's test code. Use `Clock.fixed(Instant.parse("2026-01-01T00:00:00Z"), ZoneOffset.UTC)` injected via constructor/`@BeforeEach`. **Enforcement reach:** `NO_DIRECT_TIME_ACCESS` runs from `com.homesynapse.app`'s test classpath, so it mechanically catches PRODUCTION code in every non-whitelisted module (plus app's own tests) — it does **not** scan this module's test source set. Clock-injection here is a self-enforced project convention that PM review, not `./gradlew check`, enforces. (`LockSupport.parkNanos` is a park, not a clock read — the FIX-1b precedent.)
- The cursor advances past FILTERED positions too (a non-matching position is "delivered" for the cursor's purpose); the checkpoint is written only after a matching SUCCESS — so the persisted floor can sit below the cursor by the count of non-matching positions; on restart REPLAY re-reads those and filters them again. State this in the MODULE_CONTEXT.
- The atomic projection (`state_projection`, AMD-45 §2.2): the cursor advances; the bus-side checkpoint write stays skipped; its own sink is untouched.
- LTD-11: no `synchronized`; the cursor is an `AtomicLong` CAS-max; the mode CAS stays where it is.
- The re-entrant publish (Doc 01 §3.4 "Re-entrant event production"): a subscriber that publishes from inside `onEvent` wakes itself; with the read-forward that is one extra empty page at most — no special case.
- `pendingDepth` and the `pending=` reading change meaning (hints, not undelivered positions): rename in the diagnostic (row 9), say so in the return; the FIX-2b-i thread dump is unchanged.
- Zero change outside `core/event-bus` production code except the config call sites; nothing under `core/automation`, `api/`, `web-ui/`.
