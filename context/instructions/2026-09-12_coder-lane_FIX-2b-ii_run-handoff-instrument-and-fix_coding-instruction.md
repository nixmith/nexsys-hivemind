## §1 What this implements
Sample #11 (`bd5d35e`, run 34670078359) showed the bus idle after `automation_triggered` was published: `pending=0` on every subscriber, the engine's virtual thread parked at `InProcessEventBus.liveLoop:536`, no pinned trace, no thread with a `StandardRunManager` or `StandardActionExecutor` frame. The run pipeline's hand-off is a per-run virtual thread named `automation-run-<automationId>-<runId>` (`StandardRunManager:570–:575`), started at `:320` (admitted) or `:539` (drained) right after `publishTriggered`; `runBody` (`:459`) calls `StandardActionExecutor.execute` (`:172`), whose first act per action is `publishStarted` (`:183`). Nothing in that path logs at INFO today (`git grep -n 'LOG\.' -- core/automation/src/main/java/com/homesynapse/automation/StandardRunManager.java core/automation/src/main/java/com/homesynapse/automation/StandardActionExecutor.java` = three ERROR sites: `:450`, `:738`, `:404`).

Two readings of the soak's stall survive the dump, and the dump cannot separate them: (a) the VT was started and never mounted — a started, never-mounted virtual thread shows JDK frames at most, so `BusThreadDump`'s filter hides it (name not `hs-`, no `com.homesynapse` frame within `FRAMES_SHOWN = 12`; 16 of 36 threads were hidden in sample #11; reasoned from the filter, not measured on a dump); (b) the VT mounted and died before `publishStarted` — `runBody` catches `RuntimeException` only (`:486`), so an `Error` escapes with no log line, `finalizeRun` never runs, and the run stays in `activeRuns`.

The census's red is a third thing. The v70 frame audit read `SqliteCheckpointStore.writeCheckpoint` as fire-and-forget. It is not: `WriteCoordinator.submit` returns the operation's result and `PlatformThreadWriteCoordinator.submit` blocks on `future.get()` (`:69–:97`; the interface's javadoc `:40–:42`: "The calling thread blocks until the operation completes"); the write connection is autocommit (`grep -rn 'setAutoCommit(false)' core/persistence/src/main` = `AtomicCheckpointWriter:271`, `MigrationRunner:386` only). So when `liveLoop` returns from `writeCheckpoint` the row is written and visible. `bus.position_census: subscriber=automation_engine matched=24 delivered=23 missed=1 first_missed=24 checkpoint=23 dlq=0 pending=0` — identical in samples #11 and #12 — is a real miss of the head position by the engine (`SubscriptionFilter.all()`), not a token artefact. The offer path has one silent branch that can produce exactly that: `notifyEvent`'s checkpoint guard (`InProcessEventBus:369–:373`, `if (checkpoint >= globalPosition) continue;`). For a LIVE subscriber that skip is never legitimate — a LIVE subscriber learns a position only from the notify that would offer it — so the skip becomes an anomaly kind.

Part (i) makes the next red name the step. Part (ii) is the fix for whichever row the red names.

## §5 What to watch out for
- The paste-block of record: **Tests must inject `Clock`.** Do NOT use `Clock.systemUTC()`, `Instant.now()`, `System.nanoTime()`, or `System.currentTimeMillis()` in this module's test code. Use `Clock.fixed(Instant.parse("2026-01-01T00:00:00Z"), ZoneOffset.UTC)` injected via constructor/`@BeforeEach`. **Enforcement reach:** `NO_DIRECT_TIME_ACCESS` runs from `com.homesynapse.app`'s test classpath, so it mechanically catches PRODUCTION code in every non-whitelisted module (plus app's own tests) — it does **not** scan this module's test source set. Clock-injection here is a self-enforced project convention that PM review, not `./gradlew check`, enforces.
- Line A at the admitted and drained sites goes BEFORE `.start()`, so the line exists even when the VT never runs; that ordering is the instrument.
- `run.vt` is assigned inside `startRun` under `stateLock`; at `:319–:320` it is non-null for an admitted run. Do not dereference `run.vt` on the `condition_not_met` or `failed_closed` paths (it is null there) — log `thread=none`.
- Line B runs on the VT: `[%thread]` in `logback-test.xml`'s pattern already prints the VT's name; keep the explicit `thread=` field anyway (the JSON dump and the census key on it).
- The uncaught handler must not swallow: log, then let the `Error` propagate (do not catch it in `runBody`; that is part (ii) row (b)).
- Kind E's guard is `mode == LIVE` read under the same `rwLock.readLock()` the loop already holds; do not take `queue.lock()` for it.
- `BusSoakIT`'s anomaly count now includes kind E by construction; that is intended (a sample vetoes a green, never grants one).
- The census line's `runId` comes from the store, not the log: the newest `automation_triggered` envelope's payload `runId` (see `AutomationTriggeredEvent`).
- Instruction prose vs the Files table: the table wins; flag a conflict as `[INFO]`.
