## §4 Technical specification
**Row 1 — the handler.** `static final int CLUSTER_ID = 0x0400; ATTRIBUTE_MEASURED_VALUE = 0x0000; INVALID_MEASURED_VALUE = 0xFFFF (long); TOO_LOW_TO_MEASURE = 0 (long)`. `normalize(endpoint, clusterId, attributes)`: `Object v = attributes.get(0x0000)`; if `v instanceof Long raw && raw >= 0`: `raw == 0xFFFF` → `List.of()` (the invalid sentinel never observes — F-9); `raw == 0` → `illuminance_lux 0.0`, raw `"0"` (ZCL8 §4.2.2.2.1: "0x0000 indicates that the illuminance is too low to be measured" — the device's own statement of darkness; emitting nothing would leave the last daylight value standing after dusk, which is the lie F-9 forbids — DP-1, pushback welcome); else `lux = Math.pow(10.0, (raw - 1) / 10_000.0)` rounded to one decimal (`Math.round(lux * 10.0) / 10.0`), emitted as `new NormalizedAttribute("illuminance_lux", <double>, "lux", String.valueOf(raw), "log10x10000+1")` — the fifth field is `rawProtocolUnit` (`NormalizedAttribute.java` :28–:33; the meters write `"mult=1 div=1"` there — `ElectricalMeasurementHandler` :30; the humidity handler writes `null`) — write the dialect string so a reader of the bundle can re-derive lux from the raw. Anything else → `List.of()`. Worked values (ZCL8 §4.2.2.2.1, MeasuredValue = 10,000 × log10(lux) + 1): 1 → 1.0 · 10,001 → 10.0 · 20,001 → 100.0 · 25,001 → 316.2 · 30,001 → 1000.0 · 65,534 → 3,575,197.2 (the largest valid) — re-derive each independently before pinning (law #4). Thread-safe, stateless, javadoc in the humidity handler's form.
**Row 2 — the factory.** `handlers.put(IlluminanceMeasurementHandler.CLUSTER_ID, new IlluminanceMeasurementHandler(device, clock));` after the humidity line; the counts in the class javadoc and `forDevice`'s.
**Row 3 — the classifier.** `boolean hasIlluminance = in.contains(IlluminanceMeasurementHandler.CLUSTER_ID);` beside the other flags. After `classified = withMeters(classified, descriptor);` add `classified = withIlluminance(classified, descriptor);` — a private static method in `withMeters`' shape: when `descriptor.inputClusters()` contains 0x0400 and `classified` is present, return the classification with `StandardCapabilities.illuminanceMeasurement()` appended to its capability instances (the device type is a hint, never the key — the R2/IR-24 comment applies verbatim). The fallback: before the DP-7 battery-only row, `if (hasIlluminance) return Optional.of(new Classification(EntityType.SENSOR, capabilities(illuminance, [battery])))` — an endpoint whose only recognized measurement is light is a SENSOR (EntityType :75 names illuminance among the sensor kinds); `withIlluminance` must not add the capability twice on this arm (guard by `anyMatch` on the capability id, or add it only in the post-processing and let the fallback row build the SENSOR with battery alone — the Coder chooses and the test pins exactly one `illuminance_measurement` instance).
**Row 4 — the reporting default.** `Map.entry(0x0400, new DefaultRow(0x0000, 0x21, 10, 3600, 1000))` — uint16 (0x21), min 10 s, max 3600 s (the row family's values), reportable change 1,000 log-units (= a factor of 10^0.1 ≈ 1.26 in lux; the smallest change a household automation would act on; the temperature row's 10 = 0.1 °C and humidity's 100 = 1 %RH are the siblings). The attempt is recorded as a device fact whatever the device answers (the class javadoc's rule) — so an SNZB-06P24 that refuses configure_reporting on 0x0400 records that fact and nothing breaks (DEVICE-SET :72's open question is answered by the record, not assumed here).

## §9 What to watch out for
- **Tests must inject `Clock`.** Do NOT use `Clock.systemUTC()`, `Instant.now()`, `System.nanoTime()`, or `System.currentTimeMillis()` in this module's test code. Use `Clock.fixed(Instant.parse("2026-01-01T00:00:00Z"), ZoneOffset.UTC)` injected via constructor/`@BeforeEach` (the module's tests use `TestClock.createDefault()` — follow them). **Enforcement reach:** `NO_DIRECT_TIME_ACCESS` runs from `com.homesynapse.app`'s test classpath, so it mechanically catches PRODUCTION code in every non-whitelisted module (plus app's own tests) — it does **not** scan this module's test source set. Clock-injection here is a self-enforced project convention that PM review, not `./gradlew check`, enforces.
- Uint16 arrives UNSIGNED as a `Long` (the humidity handler's comment): 0xFFFF is 65535L; never compare against a negative sentinel.
- The double: pin with `isEqualTo(316.2)` after the one-decimal rounding, never `isCloseTo` on an unrounded value — the rounding IS the contract.
- The fallback ordering: the illuminance-only row goes BEFORE the DP-7 battery-only row and AFTER the occupancy/IAS row; do not let a 0x0400 + 0x0406 endpoint fall to the SENSOR row (T8 pins BINARY_SENSOR).
- `-Xlint:all -Werror`: the explicit no-arg test constructor with its javadoc, as every test class in the module carries.
- No log token is added; if you add one, it needs a `containsExactly`-free home and a MODULE_CONTEXT row — prefer none.
