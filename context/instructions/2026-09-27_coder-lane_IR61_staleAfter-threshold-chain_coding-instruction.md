## §1 What this implements
Doc 03 §3.8 (AMD-11; `homesynapse-core-docs/design/03-state-store-and-state-projection.md` :399–:434) designs staleness as a per-entity threshold resolved from three sources in priority order — (1) a per-entity override (§9 config), (2) a capability-based default (`expected_report_interval` declared by the capability schema), (3) a global default — with `staleAfter = event.eventTime() + resolvedThreshold` recomputed on every `state_reported`, `stale` derived at read time, and `staleAfter` null (never stale) when no source applies. AMD-53 §2.2 records that "threshold resolution is not yet wired" (`AMD-53_Timestamp_Model_Unifier_Event_Time_Activity_Timestamps.md` :78) and excludes `staleAfter`/`stale` from the event-time rule (AMD-53-INV-02). At `e96dce8` the projection carries `prior.staleAfter()` on every branch and seeds null (`StateProjection.java` :810–:819, :1004–:1016 — `grep -n staleAfter` = 9 hits), the read path already derives `stale` (`MaterializedStateQueryService.java` :212–:231), the checkpoint serializer persists it (`git grep -n staleAfter -- core/persistence/src/main` = 8 hits) and the wire carries both fields (`contract.ts` :273–:274) — every metered entity has read `staleAfter: null`, `stale: false` forever (the CHAR bundle's nine bodies; G4-2's 12.5-min silence read fresh, the v81 b4/b6 audits). This WU: (a) `StalenessThresholdResolver` (state-store) — the seam the projection consults; (b) `Capability.expectedReportInterval()` (device-model) — source 2 declared where Doc 03 says it lives, with `PowerMeter` declaring 180 s; (c) `RegistryStalenessResolver` (state-store) — sources 1 → 2 → 3, with the entity's threshold the SMALLEST declared interval among its capabilities (any attribute's report resets the clock, so the most demanding capability governs); (d) the projection's `state_reported` branch writes `staleAfter = stamp + threshold` (or null) and `stale = false`; (e) the composition root wires the resolver with an empty override map and no global default (the §9 config keys are IR-61b — §11); (f) tests first, including one lifecycle IT that reads `stale: true` through the real read path after the clock passes the threshold. OUT: the passive scan and the `state_stale` / `state_stale_cleared` events (§3.8's second half — IR-61b), the §9 config schema (IR-61b), per-attribute staleness (an AMD; the review's C2), the bench's reading of `stale` (VERIFY-72H's charter).

## §4 Technical specification
**DP-1 — the seam.** `StalenessThresholdResolver` lives in `com.homesynapse.state` (exported; it names `EntityId` from `com.homesynapse.device`, which state-store already `requires transitive` — no `-Xlint:exports` trip) and `java.time.Duration`. `none()` is the default for every existing construction path so that every existing test and the IT harnesses stay byte-identical.
**DP-2 — source 2 lives on the capability.** Doc 03 §3.8 says the capability schema "may declare an `expected_report_interval`"; the Java home for a schema-level declaration is the sealed `Capability` interface — a `default` method so the 17 permitted records compile untouched (`grep -c 'implements Capability' core/device-model/src/main/java/com/homesynapse/device/*.java` = 17) — with `PowerMeter` overriding it. `energy_meter`, `power_measurement`, the three measurement sensors, the binary sensors, the actuators: EMPTY in this WU (the sensors report on change or at a 3600 s max interval; a default there would false-flag a steady room — IR-61b decides them with data; §10).
**DP-3 — the resolver.** `CapabilityInstance` carries the capability's ID, not the object (`CapabilityInstance.java` :33–:42), so the resolver resolves ids through a map built once from `StandardCapabilities.all()` (:68–:86); an entity's threshold is the MINIMUM of its capabilities' declared intervals (a plug with `power_meter` 180 s and `energy_meter` empty → 180 s; the rationale: any `state_reported` on the entity resets `staleAfter`, so the most frequently reporting capability sets the honest expectation). Sources in order: `overrides.get(entityId)` → the capability minimum → `globalDefault` → `Optional.empty()`. A registry miss falls through to the global default (a never-registered entity has no capabilities; the projection may see its report before the registry — Doc 03 §2.2's authority split).
**DP-4 — the projection.** Only the `state_reported` branch changes: `staleAfter` from the resolver on the EVENT-TIME stamp (`stamp` at :805 — AMD-53-INV-02: `staleAfter` is event-time-derived and deterministic; a target for real-time comparison), `stale = false` (the report clears staleness — Doc 03 §3.8 "resets `stale` to `false`, recomputes `staleAfter`"). REPLAY and LIVE alike (`staleAfter` must be current after replay — §3.8). Every other branch keeps `prior.staleAfter()`, `prior.stale()`. The scan and the two events are OUT (IR-61b); the read path's lazy derivation is the wire's truth for this WU.
**DP-5 — the composition root.** `HomeSynapseCore` :590 builds `entityRegistry` before :619 builds the projection; the resolver is built between them. `overrides = Map.of()` and `globalDefault = Optional.empty()` until IR-61b lands the §9 keys (`default_staleness_threshold`, `staleness_overrides` — Doc 03 :747, :754; `git grep -n 'staleness_overrides\|default_staleness_threshold' -- config/ app/ = 0 hits` at `e96dce8`).
**DP-6 — the numbers.** 180 s for `power_meter`: 3 × the TR3's ≈ 60 s cadence and 36 × the Gen4's ≈ 5 s (the CHAR audit's nine ages; the METER-3 windows 30/180/30 s are the BENCH's per-plug freshness for a single REP, a different question from the core's per-entity threshold). The number is a design number: pushback with a measurement is welcome; the override map is the per-device escape hatch once IR-61b lands.

## §9 What to watch out for
- **Tests must inject `Clock`.** Do NOT use `Clock.systemUTC()`, `Instant.now()`, `System.nanoTime()`, or `System.currentTimeMillis()` in this module's test code. Use `Clock.fixed(Instant.parse("2026-01-01T00:00:00Z"), ZoneOffset.UTC)` injected via constructor/`@BeforeEach` (lifecycle's ITs use the shared `TestClock` — follow `LinkReadIT`). **Enforcement reach:** `NO_DIRECT_TIME_ACCESS` runs from `com.homesynapse.app`'s test classpath, so it mechanically catches PRODUCTION code in every non-whitelisted module (plus app's own tests) — it does **not** scan this module's test source set. Clock-injection here is a self-enforced project convention that PM review, not `./gradlew check`, enforces.
- `staleAfter` is computed from the EVENT-TIME `stamp` (:805), never from `clock` — AMD-53-INV-02; `stale` is never computed in the projection from the clock (the read path does that).
- `Optional` as a record-method return is fine; `Optional` as a field or a constructor parameter (`globalDefault`) is a deliberate choice here for the resolver's API — say so in the javadoc, or take a nullable `Duration` and document it; the Coder chooses and the test pins one.
- The `-Werror` build: the explicit no-arg test constructor with its javadoc, as every test class carries; no unused imports.
- `StandardCapabilities.all()` is a `List<Capability>`; keying the map by `capabilityId()` — the `CapabilityInstance` on an entity carries the same id string (`capabilityId` :34).
- T6's rig: read `LinkReadIT` for how the entity is adopted and how state is read; do not add a bench dependency; the shared `TestClock` is advanced, never a real sleep.
