## §1 What this implements
**IR-46** (LINK-READ's finding, 2026-09-21; TRIAGE v101 b5 PRE-RUN): a `RuntimeException` thrown by any ingestion handler leaves `processCycle()`, `runCycleOnce()` and `productionLoop()` (rows 1–3) — the adapter's `run()` ends, the supervisor classifies and restarts it, and every frame the cycle had already drained is lost. The design decision IR-46 asked for is ruled here by layer: **a frame survives-and-counts** (a bad frame is data — the rest of the batch is processed; one WARN per key, then DEBUG; a counter); **a cycle survives a transient failure and fails fast on a persistent one** (the same three-strike rule the loop applies to keepalive misses, row 6: the third consecutive failed cycle rethrows, and the supervisor's restart — today's only behaviour — is reached after 150 ms, not never).
**IR-119** (the BC7b intake; the exhibit at D-v98-3): the window's close is a store row with no log line, so a log reader cannot see a window end (row 7). One INFO line at the close, beside the open line's form.
**IR-95** (EXPORT-1's finding; `SKIPVOC: count` RULED D-v92-13): a CommandAction whose targets are all skipped for unavailability — or that resolves to no target — completes `success` (row 9) while the run's `command_count` says 0; "the automation has never been observed to command anything" was invisible on the action row. After T-B: the action completes **`skipped`** (the vocabulary already holds it — `AutomationActionCompletedEvent.java:15`; the InterruptedException arm already uses it, row 10), the run's **`automation_completed` carries `skippedUnavailable`** (the count of targets skipped for unavailability across the run), and `command_count`'s meaning is pinned by a Delay+Command test.

## §4 Technical specification
### §4.1 The frame survives (T-A) — `Z/ZclIngestionUnit.java`
- **The per-frame guard.** Each iteration of `processCycle()`'s loop (row 3) dispatches inside ONE `try { … } catch (RuntimeException failure)`; the catch logs **`zigbee.ingestion_frame_failed: frameId=0x{} failure={}: {}`** (the frame id in hex, the exception's simple class name, its message) at WARN the FIRST time per key `(frameId, exception class)` and at DEBUG after, increments `frameFailures`, and the loop CONTINUES to the next frame. `InterruptedException` is not in scope (none is thrown on this path); an `Error` is not caught.
- **The per-handler guard.** Inside `route()`, AFTER the sender is resolved (row 4), the dispatch of a resolved HA frame (the counter increment, the liveness feed, `handleZcl`, the listener's `onFrame`) runs inside ONE `try/catch (RuntimeException failure)` that logs **`zigbee.ingestion_handler_failed: device={} cluster=0x{} failure={}: {}`** at WARN the FIRST time per key `(device, cluster)` — the `nameUnscaledOnce` form, row 5: a `Map<Long, Set<Integer>>` — and at DEBUG after, increments the SAME `frameFailures`, and returns (the frame is dropped; the next frame is unaffected).
