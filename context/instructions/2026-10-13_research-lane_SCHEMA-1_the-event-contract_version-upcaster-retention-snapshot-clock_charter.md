## §1 The questions (each answered as a rule, with its price)
1. **The envelope's version and the payload upcaster.** Today: `schema_version` per row; one hand-cut gate (AMD-52) for `state_changed` v1→v2; `DegradedEvent` for the unreadable; a value-upcaster SPI (AMD-47) for attributes. Write the rule: when a payload changes shape, what increments, where the upcaster lives (read-side, keyed on `(event_type, schema_version)`), what a reader does with an unknown version (degrade, never fail the boot), and the **golden-bytes corpus** per `(type, version)` that pins every past shape (J3 T-B's eighth component rode Jackson's zero-fill — name the test that would have caught a silent change). Prior art: Event Store's upcasting; Axon's upcaster chain; Marten's event versioning — by title, one line each.
2. **Retention by correlation chain, priced.** `RetentionPolicy(7, 90, 365)` by priority would delete the `state_changed` rows an explanation needs (HORIZON-1 F2). Write the predicate: a chain (`correlation_id` / `causation_id`) is retained whole while any member is inside its window; what is NEVER deleted (the registry's four types; `command_issued` and its terminal); what the `state_reported` stream (64 % of rows at the rig) is allowed to lose and after how long. Price it against §0b row 9 at three reporting postures (the rig's; a household with metering plugs reporting every 60 s; every 600 s) → GB/yr per home for each, and the SD-vs-SSD line.
3. **The snapshot rule (Nick, 2026-10-13: "a boot that scales with the whole store will beat any fixed gate eventually").** The registries now rebuild by index (K-4: 4 ms); which other projections still walk the log from 0 at boot or per poll (the explain projection's type scans — F18; the state projection's view snapshot, `StateProjection.java:723` "what invalidates it" is an open question) — list them from the code with their cost class. Write the rule: a projection checkpoints at H with its state durable, and a boot reads (checkpoint, tail]; the instrument that proves it (boot-to-ready vs store size, measured at BC10's cold start and at Sunday's rehearsal — the hub's rows).
4. **The clock after a power cut (A2).** `ingestTime`/`eventTime` are wall-clock; nothing disciplines the clock at boot; after a cut that also takes the router, events carry an unsynchronized clock until NTP returns. Write the rule: does the envelope carry a clock-quality mark (and where — a column, a payload field, or a separate `clock_stepped` event), how a reader treats a stepped interval, and what `globalPosition` (the safe order) already gives. Decide the cheapest honest answer; the K2 lookup degrades to its type scan either way.
5. **`logical_time` / `node_id` (R8).** Reserved, written 0. One page: what a multi-hub future would need the envelope to have reserved (an HLC's shape), and what is already enough — so that nothing in 1–4 forecloses it.
