## 2026-07-02 | Category: module-boundaries | Source: M7.5c-a (internal-read envelope conformance) — "reuse the envelope machinery" can mean an inline IDIOM, not a helper; and a frozen contract's field vocabulary may not exist in the tree — derive from the closest in-tree vocabulary and document the mapping
**Discovery:** Two pre-verify surprises. (1) The instruction assumed the conforming endpoints build `{data, meta}` "via an existing helper + `ResponseMeta`-equivalent" — but NO shared envelope helper exists in `api/rest-api`: all seven conforming handlers hand-build the same `LinkedHashMap` meta block (`viewPosition` + `clock.instant().toString()`) + `X-HomeSynapse-View-Position` + weak `W/"{viewPosition}"` ETag INLINE, and the `ResponseMeta` record is a Phase-2 type no live handler touches. "Reuse verbatim" therefore means replicate the idiom exactly (the M7.5b-mirrored-M7.5a precedent — same as its inline `p:<pos>` cursor codec finding), NOT invent a helper mid-WU: extracting one only for the two new endpoints would CREATE the second envelope mechanism the instruction forbids, and migrating all nine handlers is an unauthorized refactor. (2) The frozen A5 field `parkedSubscribers` names a vocabulary the tree lacks — `SubscriberMode` is `{COLD, REPLAY, TRANSITION, LIVE, SUSPENDED}`, no PARKED. In-tree, "parked" is DLQ-ENTRY vocabulary (`SubscriberDlq`, `parkedAt`, `oldestParkedAt`), so the faithful derivation is "subscribers with parked entries" (`dlqDepth > 0`), NOT "mode == some parked-like mode"; a SUSPENDED subscriber stays visible via the additive per-subscriber `mode` field.
**Detail:** The STOP-condition in such a pre-verify gate is usually scoped ("STOP if the helper is not reusable from these endpoints' package") — when the observed reality differs from the gate's ASSUMPTION but not its CONCERN (here: everything lives in one package, so nothing forces duplication of a second mechanism), the right move is proceed-on-the-observed-pattern + report the observation verbatim, not STOP and not improvise a new abstraction. For the vocabulary gap: map the frozen field to the nearest in-tree semantic, state the derivation rule in the handler Javadoc AND the MODULE_CONTEXT row (so the next reader doesn't "fix" it to mode-based), and flag the plausible alternative (include SUSPENDED?) for the PM ruling rather than silently choosing the wider set. Also worth pinning: when a frozen data field needs a value the endpoint's module must not import (A4's `lagEvents` needs the event-log head, but rest-api must not require event-model), the established shape is a `java.base` supplier threaded from the composition root (`LongSupplier logHead = eventStore::latestPosition`) — same pattern as the existing `viewPositionSupplier`; and when the authoritative constant is an inline literal at the composition root (the projection version `5` at `StateProjection.create`), hoist it to a named constant there and pass it through, so the wire field and the projection can never diverge — a cited-but-duplicated literal is the drift the "locate its authoritative source" clause exists to prevent.
**Impact:** (1) Pre-verify the FORM of "existing machinery" before assuming a callable helper — in this repo the envelope, the cursor codec, and the ETag are all inline idioms; conforming means byte-level idiom replication, and any helper extraction is a separate, all-call-sites refactor WU. (2) A frozen-contract field name is not evidence the vocabulary exists in the tree — derive from the closest in-tree concept, document the derivation at both the handler and MODULE_CONTEXT, and route genuinely ambiguous inclusions to the PM. (3) Cross-module values enter rest-api as `java.base` suppliers/params from the composition root, never as new module edges. (4) Hoist an inline authoritative literal to a named constant at its owning site when a second consumer appears; never mint a second cited copy.

## 2026-07-02 | Category: test-code / compile | Source: M7.5c-a gate round 1 (hub-applied 2-line fix) — AssertJ `containsExactly` on a wildcard-typed actual is a varargs-capture compile error; the codebase idiom is the `@SuppressWarnings("unchecked")` typed-local cast
**Discovery:** `assertThat((List<?>) map.get(k)).containsExactly("x")` fails `compileTestJava`: the actual's element type captures as `CAP#1`, and `containsExactly(CAP#1...)` cannot accept `String` (varargs mismatch). Production compile was GREEN — the class is test-only and compile-time, and the lane's sandbox could not run the targeted compile (build-logic bootstrap fails on the mount + VM JDK 11 vs 21), so it survived to Nick's gate despite the instruction's compile-before-handoff step.
**Impact:** (1) Never assert element CONTENTS through a wildcard-typed actual — use the conforming idiom (`ListEntitiesEndpointTest` L83–88): `@SuppressWarnings("unchecked") List<String> xs = (List<String>) map.get(k);` then assert on the typed local. `(List<?>)` casts are fine for `hasSize`/`get(i)` only. (2) Environment corollary: when the lane cannot compile in-session, every compile-only defect lands on the host gate — weight self-review toward compile-sensitive spots (generics/varargs/capture), or route compile-heavy WUs to a host-side Coder (Claude Code) where the targeted loop runs in-session.

## 2026-07-02 | Category: concurrency/design | Source: M9.1 (integration spine) — a supervisor that restarts hosted workers needs THREE ownership disciplines, and an adversarial-review fleet found all three missing on the first cut

**Context:** `StandardIntegrationSupervisor` hosts adapters on per-adapter threads with restart cycles (`restartIntegration`, TRANSIENT backoff relaunch) and a grace-bounded `stop()`. The first implementation compiled clean in review (zero signature errors across a 6-dimension source-verifying fleet) but carried FOUR confirmed lifecycle bugs, all instances of missing ownership discipline.

**The three disciplines (bake into any supervisor-shaped WU):**
1. **Irreversible resources must be re-created on relaunch.** `ExecutorService.shutdownNow()` is permanent; a `final` per-worker executor + a stop-then-start path = a "restarted" worker that silently rejects all work forever while reporting HEALTHY. Any resource killed by the stop half must be recreated by the start half (`if (executor.isShutdown()) executor = newExecutor(...)` under the state lock) — and the field's javadoc must say WHICH lifecycle events kill vs. recreate it.
2. **Loop threads need generation identity, not just a shutdown flag.** A boolean `shuttingDown` that the restart path RESETS resurrects any thread that survived its interrupt past the join grace (wedged JNI read — the exact SERIAL case Doc 05 anticipates): the zombie re-enters the FSM and un-hosts the NEW generation's worker. The guard is identity, not state: the loop only acts while `runtime.runThread == Thread.currentThread()` (checked at loop top, after run() exit, and before hosting a relaunched adapter), and clears the field in a `finally` ONLY if it still owns it.
3. **Exactly one party closes — claim, then close.** When both a supervise loop (spontaneous crash path) and `stop()` can tear down the same worker, close-the-local-reference races into concurrent double-close (the `IntegrationAdapter.close()` contract is sequential-idempotent only). The fix is an atomic claim: compare-and-null the hosted reference under the lock and close ONLY what you claimed; the party that lost the claim also skips the lifecycle-event publish (else duplicate `integration_stopped`).

**Also:** a `join(grace)` interrupted by the CALLER's interrupt is not the closee overrunning its grace — restore the flag and stop waiting, but do NOT interrupt a compliant closer (that punishes close() early and violates the grace contract).

**Impact:** for any future supervisor/host/pool WU (M9.2 transport threads, the post-hero breadth unit): (a) write the executor/thread/resource lifecycle table BEFORE the FSM (created-by / killed-by / recreated-by per lifecycle verb); (b) unit-test the restart verb explicitly — the M9.1 T-table covered crash-restart but not `restartIntegration`, which is exactly where the executor bug hid; (c) when the compile gate is unavailable, a source-verifying adversarial fleet (every call checked against the real declaration + per-finding refutation) is a strong compile substitute — it returned zero false compile findings AND surfaced the four real lifecycle bugs the type system cannot see.

## 2026-07-02 | Category: jpms/api-design | Source: M9.1 — two escape hatches for frozen contracts: the same-package assembly gateway (fast-stop past a frozen interface) and the static interface factory (constructing a package-private impl cross-module)

**Context:** (1) W4 demanded a fast supervisor stop on the abandon path, but `IntegrationSupervisor` is a frozen 9-method Phase-2 interface and the impl is package-private — lifecycle cannot reach a concrete-class method (the `InProcessEventBus.abandon()` precedent assumed the holder sees the concrete type). (2) B7 needed lifecycle to construct the package-private `ScopedConfigurationAccess` living in the config module.

## 2026-07-03 | Category: verification | Source: M9.2 (Zigbee transport/EZSP) — split external-standard re-derivation verdicts into WIRE constants (the standard wins; STOP on mismatch) vs POLICY parameters (the LOCKED doc wins; note the divergence); the derivation fleet caught a mis-pinned enum value the instruction never contained
**Discovery:** The pre-write derivation fan-out (one agent per protocol layer, deriving from bellows/herdsman/AN706 knowledge BEFORE comparing to the instruction's §Vectors) surfaced three divergences of two fundamentally different kinds. WIRE-class: the ASH duplicate-frame rule was over-generalized in the instruction (only the duplicate of the last-delivered frame re-ACKs; a genuinely out-of-sequence frame enters the reject condition and NAKs) — the standard wins, the implementation follows bellows/AN706. POLICY-class: Doc 08's "5 consecutive ACK timeouts → FAILED" matches NEITHER reference (bellows uses 4, the Silabs C host and herdsman use 6) — the references disagree with EACH OTHER, the parameter is interop-neutral, so the LOCKED doc's 5 is kept and the divergence recorded for doc currency instead of STOPping. A third case dissolved on inspection: "≥ 2 s RSTACK wait" is satisfiable by the standard's own T_RSTACK_MAX = 3.2 s — pick the value that satisfies both. Separately, the POST-write residual-constant pass (live-fetching bellows sources for the constants my own memory had flagged as moderate-confidence) caught SL_STATUS_NOT_JOINED mis-pinned as 0x0B (= SL_STATUS_IS_WAITING; correct value 0x0017) — a value the instruction never mentioned, introduced by coder memory, that would have broken v14 resume with no test failing (the fake NCP scripts whatever constant production defines).
**Impact:** (1) Classify every derivation mismatch before reacting: a WIRE mismatch (bit layouts, CRC parameters, enum values, struct offsets) is a STOP/fix — garbage on the wire; a POLICY mismatch (retry budgets, timeout counts) where references also disagree among themselves follows the LOCKED doc and gets a currency note. (2) Any constant you pin from MEMORY at moderate confidence must go on an explicit residual-verification list resolved against fetched sources before handoff — self-consistent fake-driven tests CANNOT catch a mis-pinned protocol constant (the fake speaks whatever dialect production defines); flag the ones that stay memory-only as bench-verify items. (3) The two-pass shape (derive-before-write, verify-residuals-after-write with live source fetches) is cheap relative to one wrong enum value surviving to silicon.

## 2026-07-03 | Category: testing | Source: M9.2 — deterministic serial-protocol testing: the fake channel ADVANCES the injected TestClock by the full requested wait on empty reads, and a reactive fake NCP built on the production codec gives full-stack protocol tests with zero real waits
**Discovery:** Every ASH/EZSP timeout path (adaptive ACK band, 5-timeout FAILED, per-command timeouts, probe step budgets, watchdog idle) became instantly and exactly testable with one fake-channel convention: `read(buffer, maxWaitMillis)` returns queued bytes when present, else advances the shared TestClock by maxWaitMillis and returns 0. Production deadline loops (`remaining = deadline - clock.instant()`) then terminate deterministically with EXACT elapsed arithmetic assertable (e.g. 1600 + 4×3200 for the five-timeout path; 8200 ms for the silent probe). Layered on top, a FakeNcp write-handler parses the host's frames with the SAME codec production uses (whose correctness is separately pinned by independent byte vectors: the AN706 example frame, the LFSR keystream, two CRC check values), auto-RSTACKs, auto-ACKs, and answers EZSP commands from a pluggable function — full-stack protocol tests (negotiation tiers, single-in-flight under concurrent VTs, formation byte-structs) with zero real serial I/O and zero Thread.sleep.
**Detail:** Two traps worth carrying. (1) If production FLUSHES input before a handshake (connect/probe), pre-enqueued fake responses are wiped — script reset/probe responses REACTIVELY via the write-handler, never by pre-enqueueing. (2) The codec-based fake is only non-circular because the codec itself is pinned by INDEPENDENT external vectors in a separate test class; without those, fake-vs-production round-trips would happily agree on a wrong wire format. Related review catch: a test helper that strips a framing byte must receive un-stripped input — a double-strip produced a deterministic CRC-reject that an LLM read-pass missed and the adversarial refuter confirmed bit-exactly (the compile/test gate class, caught only because the fallback review re-simulated the codec).
**Impact:** For any timeout-rich byte-protocol unit: (a) make the fake channel's empty-read advance the injected clock by the requested wait — every timeout path becomes exact-arithmetic-assertable with no wall time; (b) build the reactive peer simulator ON the production codec and pin that codec separately with independent external vectors (the involution/keystream/check-value trio); (c) respond reactively to writes when production flushes; (d) when a helper both strips framing AND parses, audit every call site for double-stripping — it fails deterministically but compiles cleanly.

## 2026-07-04 | Category: testing / value-model | Source: M9.3 (WithinTolerance A10) — `QuantityValue` normalizes to CANONICAL units in its compact constructor; a test fixture that hands it a protocol unit gets a silently converted magnitude

`new QuantityValue(126.0, "K")` is temperature-Kelvin and becomes −147.15 °C before `evaluate()` ever sees it — the ±band test then fails mysteriously on a correct implementation. The catalogue conversion is a FEATURE of the value model (canonical-at-construction), not a bug; the lesson is fixture discipline: when a test needs a raw magnitude through a `QuantityValue`, use an identity-conversion unit ("%", "W"); and color-temp Kelvin is an `IntValue` (`color_temp_kelvin`), never `QuantityValue("K")`. Generalizes: before building fixtures on a value type, read its compact constructor — validation is visible in the signature, NORMALIZATION is not.

## 2026-07-04 | Category: protocol / dedup | Source: M9.3 (measured-contract ingestion dedup) — scope the dedup comparison to the COMMAND PAYLOAD, not the frame: the field you dedup on (TSN) is embedded inside the bytes you compare

The measured duplicate pattern is "consecutive TSN + identical payload" — but the twins are only identical AFTER the ZCL header, because the TSN itself differs and lives in the header. Comparing whole-frame bytes makes the dedup structurally never fire, and every unit test that hands the deduplicator a pre-built identical array stays green while the integration path double-publishes. Two rules: (1) when a dedup contract says "identical payload," pin down which byte range "payload" means at the layer doing the comparing — exclude the fields that legitimately vary; (2) write at least one test that feeds the dedup through the REAL parse path with twins that differ exactly as the wire differs (here: the fixture-replay gate caught it same-session).

## 2026-07-04 | Category: architecture / frozen-surfaces | Source: M9.3 (interview retry + frozen DTOs) — when a frozen no-throws surface implies blocking retry semantics, move the schedule into a clock-scheduled queue and make the surface single-attempt; when a frozen record can't carry a failure state, keep a richer internal result type and render the frozen type only where constructible

Doc 08 §3.4's "retry 3× at 5/15/30 s" cannot live inside a frozen `interview()` without sleeping a thread through backoffs (NO Thread.sleep). The working shape: `interview()` = ONE attempt; retries are TIMESTAMPS in a pending queue the ingestion cycle drives (`due()`/`recordFailure()`/`onFrameReceived()`) — the sleepy park/resume machine falls out of the same mechanism for free. Similarly `InterviewResult` (non-empty endpoints, non-null identity) cannot represent a total failure: the internal `InterviewAttempt` carries gathered-data + failedStep, and the frozen record renders only when constructible (PARTIAL uses empty-string identity; the event layer maps that to its sentinel because the frozen event payload rejects blanks). Pattern name: richer-internal-currency, frozen-surface-rendered-at-the-edge (the M7.4b lesson's sibling for results instead of methods).

## 2026-07-04 | Category: event-sourcing / self-consumption | Source: M9.4a (F-2 supersession) — a subscriber that PRODUCES an event type it also CONSUMES must classify its own dispositions before terminal-matching; the bus loops every publication back

The ledger consumes `command_result` (the acknowledged/rejected correlation) and M9.4a made it PRODUCE `command_result(superseded)`. The loop-back is not hypothetical: the bus redelivers the ledger's own publication, `onCommandResult`'s (entity, command) fallback matches the NEWER in-flight command of the SAME name, and the non-acknowledged else-branch removes it and emits a spurious timeout — the hero E2E dies while every pre-existing unit test stays green (unit publishers don't redeliver). The same latent class existed for `expired_on_restart` since M7.3 (post-restart redelivery vs a re-issued command). Fix shape: a disposition guard — outcomes that are terminal REPORTS about an already-concluded command (`superseded`/`expired_on_restart`/`unconfirmed`) are skipped before the terminal-match; adapter REJECTIONS (`rejected`/`timed_out`/`unroutable`/...) still match. Two rules: (1) whenever a change makes a subscriber emit an event type in its own subscription filter, enumerate the loop-back path explicitly and write the redelivery unit test (a RecordingPublisher can't catch it — feed the published payload back through onEvent); (2) grep the consumer surfaces for the outcome vocabulary BEFORE adding values — the S4-style survey found this in minutes; the E2E would have found it in hours.

## 2026-07-04 | Category: harness / composition-root | Source: M9.4a (hero loop) — the load-validated vs trigger-time-resolved selector split decides what a boot-time config can reference; labels are the only selector that joins runtime-minted entities to boot-loaded automations

Adoption mints entity ULIDs at RUNTIME, but automation configs load at Phase 1 — `entity_ref` (unknown ULID) and `entity:` slug (load-time registry-validated, entities don't exist yet) are both unusable, and inline trigger selectors can't use `type:` (the key collides with the trigger's own `type:` — parseSelector reads the same map). `label:` is the seam: NOT validated at load, resolved at trigger time, and the test can re-register an adopted entity with a label via `updateEntity`. Same trick for action targets. Generalizes to any boot-config-references-runtime-identity test: find the selector that defers resolution to fire time, and inject the join at runtime through the registry's update surface. (Also caught: the trigger-map `type:` collision means an inline type-selector on ANY trigger is unreachable — a loader currency item for the PM.)

## 2026-07-04 | Category: instruction-verification | Source: M9.4a (identify leg + buildCommand structure) — behavioral pins can be structurally wrong two ways: where the behavior LIVES (base-final vs per-impl) and whether a mandated flow is REACHABLE through frozen gates (dispatch validation)

Two same-session instances. (1) P27 pinned "six impls ALL throw on buildCommand" — behaviorally exact, structurally wrong: ONE `public final` throw on the abstract base; filling ×3 required removing `final` (an unlisted base-class edit, declared). (2) The mandated hero leg "issue identify → dispatched frame" is unreachable through the REAL path: Tier-1 dispatch validation requires a capability defining the command, and no core capability defines identify — the profile's identify characterization WARN-skips at install (nothing to install ONTO), and the §2 test line asserting a DISABLED policy for it was unrealizable. ## 2026-07-04 | Category: protocol / await-primitives | Source: M9.4b (§5.3 NETWORK_UP await) — an await built over a single-in-flight pipeline must check the shared callback BUFFER before reading the transport; the signal may have been consumed by an earlier command's own response loop

`awaitNetworkUp()` read the transport for `stackStatusHandler(EMBER_NETWORK_UP)` — green on the FORMATION path (the callback rode the formNetwork response and stayed in the channel) and a guaranteed false timeout on the RESUME path: the callback arrived during the `networkInit` exchange, the `getNetworkParameters` command that followed READ it first, and its response loop dutifully enqueued it into `pendingCallbacks` — the await then re-read an already-answered radio until the window closed. The red §7.6 second-boot test caught it (the two paths differ only in how many commands follow the signal's arrival). Rule: in a single-in-flight pipeline where every command's read loop preserves unrelated frames into a shared buffer, ANY await-for-frame primitive must scan-and-remove from that buffer FIRST, then fall through to transport reads — and the test matrix must include a path where at least one command runs between the signal's cause and the await.

## 2026-07-04 | Category: JPMS / reflective-shape-locks | Source: M9.4b (§2.3 StateQueryService factory overload) — a lambda inside an interface's static method compiles to a SYNTHETIC interface method that reflective shape locks count; park the lambda on the impl class

Adding a 5-arg `materialized(...)` overload should have taken `StateQueryService.getDeclaredMethods()` from 6 to 7 — the shape test failed at 8 because the 4-arg overload's delegation body contained `() -> null`, which javac lowers to a synthetic `private static` method ON THE INTERFACE. Fix: hoist the constant to the package-private impl class (`MaterializedStateQueryService.NO_REGISTRY`) and reference it — the synthetic lands on the impl, whose shape nobody locks. Rule: modules with interface shape tests (`getDeclaredMethods().hasSize(N)`) must keep interface bodies lambda-free (method refs to EXISTING methods are safe; lambdas and capturing expressions are not), or the shape test should filter `isSynthetic()` — prefer the lambda-free body so the lock stays a strict literal count.

## 2026-07-06 | Category: test-harness / callback-delivery | Source: M9.4-TCJ (join-handler tests) — a callback riding a command's response is NOT in the ingestion drain until the protocol next READS; adapter-level tests must pump (ping) before cycling

The FakeNcp idiom for unsolicited callbacks is "ride them on a command's response list" — but the single-in-flight pipeline reads ONLY until its matched response arrives, so riders appended after the response sit unread in the channel. `runCycleOnce()` alone then drains an EMPTY callback queue and the test asserts against silence (the first draft of the M9.4-TCJ join tests had exactly this defect — caught in self-review by tracing the read path, before the adversarial fleet ran). The delivery step is a subsequent read: the rig's `deliverAndCycle()` idiom (`coordinatorProtocol().ping()` — the nop's response loop reads the riders, classifies them `isCallback`, and parks them in `pendingCallbacks` — then `runCycleOnce()` drains). Rule: any adapter-level test that scripts an unsolicited callback must account for WHO performs the read that moves it from the channel into the drain — in production it is `pumpInbound()`/the next command; in tests it is an explicit `ping()`. Corollary for boot-path awaits: the same rider mechanics are why `awaitNetworkUp` checks the buffered queue first (the 2026-07-04 await-primitives lesson's test-side mirror).

## 2026-07-06 | Category: test-harness / shared-fixture-modeling | Source: M9.4-NCFG (the config prelude) — a batch added to SESSION START changes frame arithmetic for EVERY scripted responder; model the NCP-side state in the shared fake (handler-precedence-preserving built-in), never by widening N per-class responders

Adding 13 exchanges (10 `setConfigurationValue` + 3 `getConfigurationValue`) inside `startSession()` put the batch on EVERY test path that negotiates a session — seven independent responder functions across six test classes plus the rig would each have needed the same ~15-line echo arm AND a per-instance value store. Instead the echo model went INTO `FakeNcp` itself as a precedence-preserving built-in: it answers ONLY when the scripted handler returned an EMPTY list (unscripted frame), so an explicit scripted NAK always wins, `null` still means silence (the timeout idiom), and RST clears the store (matching the real NCP's reset-to-defaults — which is the very premise of the WU). Result: zero per-class responder edits; the NAK/mismatch tests script their overrides exactly as before. Two rules: (1) when production gains a session-start (or any always-runs) exchange, put its happy-path model in the SHARED fake behind handler precedence — the fake is simulating the DEVICE, and device state (config memory, reset semantics) belongs there, not copy-pasted into every script; (2) never assert `receivedEzspCommands()` TOTALS or "command at index N" (except index 0 = the version frame, which negotiation-first guarantees) — count per-frame-id or filter legacy frames, because session-start arithmetic is allowed to grow. The four EzspProtocolTest count assertions that broke were exactly the ones violating rule 2; their intent-preserving rewrites (one-legacy-version-frame, second-start-adds-nothing) are STRONGER pins than the totals they replaced — "second start adds nothing" now also proves config-not-rewritten for free.

## 2026-07-06 | Category: test-harness / callback-delivery | Source: M9.4-ADP (config-accepted adoption tests) — within ONE scripted response list, riders must precede the matching response; the receive loop returns at the match and everything behind it strands

The second failure mode of the rider mechanics (the 2026-07-06 TCJ lesson covered the first): the M9.4-ADP tests DID pump correctly (`ping()` before `runCycleOnce()` — the deliverAndCycle idiom), but the handler's nop branch returned `[nop-response, rider]`. `executeLocked`'s receive loop returns AT its matched response, so the rider behind it stayed unread in the channel and every announce processed one protocol-read late — 6 of 7 tests failing, with T6 passing by coincidence of the lag (three announces happened to yield the same totals; a passing test proved nothing). The rig's `handleCommand` has the order right: queued callbacks FIRST, the command's own response LAST — that order makes the pump's read park the riders as callbacks BEFORE the loop terminates on the match. Two rules: (1) in any FakeNcp handler, a callback frame goes BEFORE the response of the command carrying it, never after; (2) a multi-round test whose totals survive an off-by-one-cycle lag is not evidence the pipeline is synchronous — assert something the lag breaks (a count after ONE round). Caught by the adversarial test-refuter lens tracing FakeNcp.apply → AshSession ack-await → executeLocked's return — the harness idiom looked byte-identical to the proven TCJ test and passed visual review; only the read-path trace exposed it.

## 2026-07-07 | Category: design-disambiguation / blast-radius | Source: M9.4-RPT (the §3 downgrade mapping) — when an instruction's vocabulary is ambiguous between two defensible semantics, enumerate which EXISTING end-to-end pins each candidate breaks; the reading that holds the invariant AND the frozen suites green is the ratified one

The §3 contract said non-VERIFIED postures downgrade to "DISABLED-with-recorded-reason or BEST_EFFORT as the ratified mapping dictates" — and the ratified mapping existed nowhere as a table (the docs agent assembled it from Doc 08 §3.6 prose, a worked example, Doc 02 §3.8, and Register §51, with the DISABLED-vs-BEST_EFFORT selector an explicit gap). The disambiguator was not more doc reading — it was blast-radius enumeration: DISABLED-for-READBACK_ONLY would flip the Hue's on_off/brightness/color_temperature policies whenever a drive degrades, and RestartHonestyIT's re-link (whose rig scripts no Bind_rsp → every bind honestly fails → READBACK_ONLY facts) would break its CT-15000 confirmationTimeoutMs pin and its state_confirmed leg — while keep-policy-BEST_EFFORT holds both the invariant (never-false-CONFIRMED is structural: CONFIRMED only renders on genuine report evidence) and every downstream pin. The instruction-level ambiguity was thus resolvable by tracing which candidate semantic the ALREADY-RATIFIED test suite contradicts.
