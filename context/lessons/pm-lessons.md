## 2026-07-03 | Category: environment / process | Source: v14 beats 48+54 (twice-paid) — a client restart rolls the CONVERSATION back, not the FILES; resume with a freshness check or you collide with your own ghost

## 2026-07-03 | Category: orchestration / dispatch-craft | Source: v14 Doc-18 research lane + FE-1b lane (both audited ACCEPT) — the dispatch prompt IS the quality gate: what you demand shapes what returns

**Discovery:** two independently-launched Cowork lanes returned near-perfectly auditable products, and the causes were prompt-structural, not luck: ordered ground-first reading lists (with WHY per item); **evidence-artifact/decision-artifact separation** (big tagged dossier + small charter → the hub audits the small one deeply, samples the big one); anti-fabrication tagging mandated with a named precedent; size caps; a fixed-constraints "not yours to relitigate" section; explicit return protocol + done-when. The lanes also improvised correctly where the prompts were silent — FE-1b proved mid-lane baseline-shift disjointness instead of stopping; the research lane deferred its shared-file append on seeing foreign uncommitted writes; FE-1b's explicit-list staging caught an untracked `dist/` before it shipped.

**Impact — fold into every future lane prompt:** (1) a mid-lane baseline-shift protocol line (HEAD moved → prove disjointness and proceed; intersecting → STOP, cross-lane event); (2) a **known-hazards line mined from prior returns in the same territory** (FE-1b lost its first smoke attempt to the token-lockout trap the hub already knew about — the hub's job is to carry hazards forward); (3) counts in returns must be re-derivable (state the command, not just the number — a 268-vs-191 tag-count ambiguity cost an audit round-trip); (4) size caps distinguish prose from evidence tables (good tables were punished by a flat cap); (5) shared-file appends defer when the file carries uncommitted foreign writes. Separate evidence from decision whenever a lane both researches and decides.

## 2026-07-03 | Category: review-finding | Source: M9.2 gate round 1 (checked-exception flow class)
**Discovery:** Checked-exception FLOW errors are structurally invisible to LLM compile review — the M9.2 coder pass AND its 6-dimension adversarial fleet (which verified signatures against real jars via javap and re-derived CRC vectors) all missed undeclared checked `PermanentIntegrationException` throws in THREE files; and javac's error-stop reported only the FIRST file, so the gate evidence understated the defect 3×.
**Detail:** The fleet's compile dimensions check symbol resolution, signatures, and lints — none model JLS §11.2.3 exception-flow analysis, and a Javadoc `@throws` that matches the throw site *looks* complete to a reviewer while still failing javac. When a gate bounce reports errors of the checked-exception class, sweep the ENTIRE module for the same class before handing back the fix (grep `new <ExceptionType>` + verify every enclosing signature); the hub's sweep turned a would-be 3-round bounce into 1. Companion architectural resolution: a checked domain exception must not be forced through a no-throws frozen interface — put the checked type on a package-private seam the adapter calls directly (`resumeStored()`/`startSession()`/`detect()`), and let the frozen surface rethrow unchecked cause-chained.
**Impact:** (1) Coding instructions that mandate a checked exception now also state WHERE its `throws` declarations land (seam map), since the frozen-interface collision is predictable at authoring; (2) gate-bounce triage always sweeps the module for the reported defect CLASS, never just the reported sites; (3) instruction-internal-consistency check gains a case: a pinned module-info/"exactly N directives" diff must be validated against every behavior the same instruction mandates (M9.2's pin forbade the org.slf4j edge its own §Vectors logging requirements forced — the [REVIEW] that ate reviewer attention was self-inflicted).

## 2026-07-04 | Category: audit-craft | Source: M9.4a two-layer audit (the refuted agent DEFECT)
**Discovery:** The dispatch-craft rule ("quote spine phrases exactly — lossy compression propagates as false corrections") applies to AUDIT-AGENT prompts exactly as it does to lane briefs. The hub's verification-agent prompt compressed the instruction's issuance-supersedes semantics into "DISABLED-mode → no expiry"; the agent then judged conforming code against the hub's phantom mandate and returned a HIGH-confidence DEFECT verdict — refuted only because layer-2 re-read the instruction and the ratified caveat text.
**Detail:** An audit agent's "mandate" IS whatever the prompt says it is — a comparator faithfully amplifies its embedded expectations, wrong ones included. Two occurrences of the same failure shape in one arc (a survey agent's verdict LABELS contradicting their own quoted evidence at v18 beat 1; a phantom mandate at beat 4) — in both cases the QUOTED EVIDENCE was sound and the judgment layer was noise, and in both cases hub direct reads of the primary text resolved it.
**Impact:** (1) When embedding expected semantics in an audit prompt, QUOTE the instruction's own sentences for anything subtle (supersession/expiry/ordering rules), never paraphrase; (2) layer-2 adjudicates every DEFECT/REFUTED verdict against the PRIMARY text (instruction + ratified doc), not against the agent's restatement of the mandate; (3) treat agent verdict labels as claims and agent quotes as evidence — the evidence outranks the label.

## 2026-07-04 | Category: authoring-craft | Source: M9.4a R1 (the IT-home deviation)
**Discovery:** A Files-table location pin is a SOURCE-STATE claim like any signature pin — it must be grounded before it is pinned. The hub pinned `testing/integration-tests` as the hero IT's home without reading that module's build file; it is `piProfile`-gated out of the default `check`, which would have silently excluded THE done-when test from every default gate and from CI. The Coder's grounded deviation (lifecycle test tree, where the harness pattern lives) was correct.
**Impact:** Any instruction row that places a NEW test in a module the WU doesn't otherwise touch gets a one-line grounding check at authoring: read that module's build.gradle.kts for test-task gating (`enabled`, profiles, tag filters) and state it in the row. A test that exists but never runs in the gate of record is worse than no test — it reads as coverage.

## 2026-07-03 | Category: anti-pattern | Source: M9.2 gate round 2 (the hub's own fix bounced)
**Discovery:** Edit-tool `replace_all` is SUBSTRING matching, not line-anchored — an 8-space-indented pattern matched inside a 12-space-indented line and rewrote the hub's own just-written helper into infinite recursion; the post-fix verification grep produced a count (24) that was arithmetically consistent with BOTH the correct and the corrupted file, and the hub read it optimistically.
**Detail:** This is the env-model §5 anchor-hygiene lesson (`find("## X")` matches prose before headings) recurring in a new costume: any indentation-prefixed pattern is a substring of every deeper-indented occurrence of the same statement. And a verification whose expected value is identical across the states it must distinguish verifies nothing. Correct forms: (a) make replace-all patterns collision-proof by including a token unique to the target sites (here: nothing — the right move was excluding the helper region or editing sites individually); (b) after ANY bulk edit, verify by READING the mutated regions, not by counting matches; (c) if counting, choose a query whose expected value DIFFERS between the healthy and corrupted worlds.
**Impact:** Bulk edits to just-authored code get the same discipline as governance-file rotations: read-back the anchor region after the operation. A gate round was spent re-learning this; the fix itself was one line.

## 2026-07-04 | Category: review-finding | Source: M9.4b grounding (v20 hub — five agent false-absences in one pass)
**Discovery:** Read-only survey agents produced FIVE confident "ABSENT" claims in a single grounding pass, every one refuted by a hub direct read — and the failure modes were mundane: searching the wrong directory (`core/configuration` for a module living at `config/configuration`), reading an INTERFACE file and reporting on the implementation (`ZigbeeAdapter` for `ZigbeeIntegrationAdapter`), and grep patterns that missed the target's actual form.
**Detail:** The refuted claims were load-bearing: "no `SecretStore`", "no `ReportingConfigurator`", "no `DegradeRule`", "no `transport_unbound` PIE", "no `HomeSynapseCore` accessors" — three would have caused the instruction to specify creating types that already exist (collision-class defects), one would have dropped a mandated custody mechanism. An ABSENT claim is epistemically stronger than a PRESENT claim (proving absence requires exhaustive search) yet agents state both with equal confidence. The two-layer rule already covers this, but the audit emphasis has been on verifying PRESENT claims (quotes-are-evidence); ABSENT claims have no quote to check — they demand a hub-side re-grep of the specific name before consumption.
**Impact:** Standing rule for grounding returns: every agent "ABSENT" that an authoring decision depends on gets ONE hub-side targeted grep (name, repo-wide, no path filter) before the pin sheet records it. Cost per claim: seconds. The same pass also validated the counter-measure — the audit round's agents were instructed to quote evidence per check and produced zero false claims.

## 2026-07-07 | Category: review-finding | Source: M9.4 iteration-3 intake (v23 hub — the entities 1-of-2 gap; the FOURTH mechanism-without-driver)
**Discovery:** Verifying the GATE is not verifying the MECHANISM behind it. The beat-4 class-sweep — run specifically to find the mechanism-without-driver class after adopt() made it three — classified reporting-config as "adoption-gated and unblocks with it" and stopped AT the gate. The gate opened on silicon (device_adopted x2) and nothing was behind it: ReportingConfigurator had NO production caller and ReportingOps NO production implementation (sole implementor = the test fake). The class hit a FOURTH time (PJ, NCFG-config, ADP, RPT), found only when /api/v1/entities returned 1-of-2.
**Detail:** Two compounding forms. (1) The sweep's stop-condition was wrong: "X is gated on Y" filed X as downstream-resolved instead of walking X's OWN caller chain through the gate (emitter + caller chain, end-to-end — the runbook-trigger lesson, which the sweep itself was applying one link short). (2) The vacuous-VERIFY corollary: runbook step-11's REPORTING-CLEAN grep passed because NOTHING RAN — absence-of-WARNs from a never-executed mechanism reads identically to success. The runbook's own parity clause ("the WARNs' ABSENCE plus reports actually FLOWING is the parity evidence") had the correction built in; the grep alone was treated as the check. A VERIFY line needs paired evidence of EXECUTION (a success INFO, a count, a flowing report), not just absence of failure lines.
**Impact:** (a) Class-sweeps for un-driven mechanisms must walk every "gated-on" edge THROUGH the gate to a production call site — the sweep terminates at code that runs, never at a classification. (b) Every runbook VERIFY whose healthy state is "no output" gets a paired positive-evidence line (the M9.4-RPT instruction mandates ONE per-device success INFO for exactly this reason). (c) Silicon evidence ordering: a state-surface count (entities 1-of-2) refuted a green-looking sweep in one query — cheap surface counts belong in every iteration's done-when.

## 2026-07-10 | Category: process / record-integrity | Source: v28 hub — the M9.6-RO record discrepancy, corrected append-only via the R1 micro-commit (folded by the v29 hub, 2026-07-11)
**Discovery:** A staged commit message asserts ONLY confirmed state — write it after the delta exists on the tree, or hold the commit order.
**Detail:** `1627978`'s staged message recorded the audit's one [REVIEW] as "CLOSED PRE-COMMIT with the by-id-pin test (suite 452/0/0)" while that closure was still an ordered-but-unexecuted correction paste; the paste landed in a fresh session that adjudicated it a duplicate dispatch and correctly VERIFIED-NOT-REDONE at 451 — the test had never been written, and the pushed message asserted a future state as fact. Corrected append-only in the R1 micro-commit's own message (`3590fca` — the OBS-2 re-attribution precedent, extended from bench records to commit messages); the R1 session then proved the test's teeth via the exact audit mutant (1-of-14 failed; tree restored byte-identical, hub-verified at the v29 launch).
**Impact:** A commit message is a RECORD — the north star's never-false-* extends to it. It asserts only what is true of the exact tree it stages, re-derived at order time (the FRESH-porcelain sweep-guard's sibling); anything pending (audits, correction pastes, CI) is named as pending or omitted.

## 2026-07-12 | Category: process / grounding-craft | Source: v30 hub — the B1 ⛔ G-B1-2 STOP (the Coder's route census refuted the hub's grounding claim)
**Discovery:** API-surface grounding verifies by ROUTE-REGISTRATION CENSUS walked to the composition root — never by type existence or javadoc route names. Type-reads ground SHAPES; only a census grounds EXISTENCE.
**Detail:** Authoring B1, the hub grepped the command types at `1aa809d`, found `CommandRequest`/`CommandStatusResponse`/`CommandLifecyclePhase` with javadoc naming both routes, and recorded "the command endpoints EXIST" in the beat-1 spine + the pushed commit message. The types were Phase-2 specification artifacts with zero production references; the wired v1.1 surface is nine GET routes (`RestFilters`), zero write routes anywhere in src/main. The instruction's own STOP gate (G-B1-2: "confirm the routes exist ... else STOP") caught the miss pre-code at desk price — zero files written; the Coder's census (registration sites + `bringUpHttpSurface` install walk + reference census + MODULE_CONTEXT's own "implementations needed" row) is the model evidence shape. This is mechanism-without-driver #7 — the class extended from log emitters and trackers to the HTTP surface: a route named in javadoc is a mechanism-without-driver until a registration site and its composition-root install are cited file:line.
**Impact:** (1) Any instruction gating on a surface existing carries the census evidence IN the instruction (registration site + composition-root install, file:line), not a types-read. (2) Hub grounding claims on the spine name their evidence class — "types + javadoc" is not "exists." (3) The well-formed STOP gate is the cheap insurance that makes a grounding miss survivable — keep writing them even for facts the hub "verified" itself; the gate caught what the hub's own summary missed.


## 2026-07-18 — Count-pin sweeps grep by MECHANISM, never by name-string (the M9.7-W2 P9 refutation)

**What happened:** the M9.7-W2 pre-verification's P9 row claimed "no test pins the bundled profile count," swept by grepping the resource-name string (`zigbee-profiles`) and `allProfiles()`. The Coder's execution-time sweep refuted it: `ZigbeeProfileLoaderTest` pinned the bundled census via `loader.loadBundled()` + `extracting(ProfileEntry::profileId).containsExactlyInAnyOrder(...)` — no resource-name string anywhere near the assertion. The pin was adapted in-session under the instruction's sanctioned P2-sweep clause; zero cost beyond the record.

**The lesson:** a count/census pin is a CONSUMER of a loading MECHANISM, not of a file name. Sweep by enumerating every caller of the loading entry point (`loadBundled()`, the registry's `register(...)`, the factory), then read each caller's assertions. Name-string greps find documentation, not consumers. This is the P2 fan-out survey's own principle applied to the pre-verification layer — the pre-verification is itself a claim set that the sweep discipline governs.

## 2026-07-18 — Suite baselines are volatile spine state: state as at-commit-X or re-derive at authoring (the 452→466 staleness)

**What happened:** the M9.7-W2 instruction's G-W2-6 gate carried "last recorded 452/0/0" — copied forward from the M9.6-RO-R1 record. The true baseline at the dispatch HEAD was 466 (M9.6-AVAIL had added +14). The Coder adjudicated non-STOP correctly (the delta explained itself), but the gate briefly pointed at a wrong number.

**The lesson:** a suite count is exactly the class of volatile state the truth-hierarchy says never to copy forward. In a STOP gate, either (a) phrase it as "forced-fresh GREEN at the dispatch HEAD — record the count" (self-deriving, never stale), or (b) pin a number ONLY with its commit ("452 at 3590fca"). A bare count inherited from a prior record is a masthead-state claim wearing a gate's clothing.
## 2026-07-19 — File-shape claims are enumerated at source at authoring, never carried from prose (the LEARN-PERSIST [INFO] pair)

**What happened:** the LEARN-PERSIST instruction told the Coder the e2e twin's "two existing methods" stay byte-untouched — the file has THREE (the count was carried from the W2-LEARN close-out prose, which described that WU's delta, not the file). The pre-verification's P8 placed the cache/ingestion construction "in the adapter ctor" — both sites live in `initialize()` (inferred from grep line numbers `:279`/`:323`, never read in context). The Coder adjudicated both conservatively ([INFO], not STOP) and the substance held, but two instruction-of-record claims were wrong in the same WU.

**The lesson:** any file-shape claim an instruction or pre-verification makes — method counts, member locations, construction sites, section boundaries — is ENUMERATED from the source file at authoring time. Close-out prose describes a DELTA; line-number greps locate TEXT; neither is a shape. The one-minute `grep -c "void " | sed -n 'contextp'` at authoring is cheaper than the [INFO] adjudication it pre-empts, and a wrong shape claim in a STOP-gated instruction is one conservative-Coder-judgment away from a false STOP.

**Impact:** (1) Instructions citing "the N existing X stay untouched" carry the enumerated list, not the count alone. (2) Pre-verification location rows quote the enclosing method/context line, not just `:NNN`. (3) This extends the enumerate-by-mechanism sweep rule (2026-07-18) from consumers to shapes.

## 2026-07-24 | Category: review-finding | Source: CMD-API two-layer audit (v36 beat 9) — hub authoring miss #2, ratified as I1
**Discovery:** SEAM-I/O — an instruction introducing a NEW HTTP verb (or any handler class consuming a request surface the codebase has never consumed) verifies at authoring that the endpoint seam can READ what the handler needs; "the seam exists" is not "the seam carries the input."

**Impact:** For every first-of-its-class handler, the authoring pass reads the seam interface and enumerates the I/O the DPs require against the methods that exist; any missing accessor is pre-designed INTO the instruction (Files table complete; the growth pattern named). Extends enumerate-file-shapes-at-source (2026-07-19) from shapes to seam CAPABILITIES.

## 2026-07-26 | Category: review-finding / verification | Source: the deploy-evening no-serve-path finding (v38 beat 7) — L1: a transitive claim is verified at EVERY hop
**Discovery:** "Verified at source" is only true if EVERY hop of the claimed chain was read. The beat-6 grounds line "installDist builds the dashboard ON the Pi — verified at source" rested on two real reads (the app's `runtimeOnly(project(":web-ui:dashboard"))` + the dashboard's npm-tasks-into-`assemble` wiring) and one unexamined inference bridging them.
**Detail:** The chain had THREE hops: (1) the dashboard module publishes an artifact, (2) that artifact rides `installDist`'s graph, (3) something serves the files. Hop 1 was false (`base` plugin, zero `artifacts` — the dependency resolves EMPTY, so hop 2 collapses too) and hop 3 was false independently (no `staticFiles` mount anywhere; Doc 13 §3.2–§3.3 was never composed). The Pi's 23s / 11-executed build was the arithmetic tell, correctly flagged by the navigator (§3.6) and confirmed at source only afterwards. The claim fed a REC whose promised same-evening banks (G2-live + FE-LIVE (a)–(c)) were never achievable — under either deploy shape.
**Impact:** Any authored claim of the form "X will happen because A is wired to B" enumerates the full hop chain and cites a read for EACH hop (artifact → graph → packaging → serving are four different facts). A cheap corroborating instrument (expected build-time/task-count arithmetic) rides the claim wherever one exists. Extends every-hop thinking from code seams (SEAM-I/O, 2026-07-24) to build/deploy chains.

## 2026-07-26 | Category: anti-pattern / security-hygiene | Source: the deploy-evening 3.1 incident + the filed-return redaction (v38 beat 7) — L3: token-paste poison
**Discovery:** A credential that enters a paste, transcript, or repo file is burned the moment it lands there — and the mint WARN line ("Token: ... shown once") is the canonical poison: it WILL ride any naive log paste.
**Detail:** The stray store's minted token rode two conversation transcripts before adjudication (nil harm only because the store it unlocked was empty, orphaned, and then deleted — the structural burn). The live store's own initial token, minted the same evening at the 17:08 boot, exists in the live boot log and in `~/.homesynapse/config/initial_api_token` / `~/hs-bench/config/initial_api_token` — and appears in NO transcript, which is the state to preserve forever. The filed deploy return REDACTS the raw value (documented in-file) because the hivemind is a pushed repo: the corpus records evidence, never credentials.
**Impact:** Standing rules: (1) glance/grep patterns in briefs stay token-scoped — never paste raw boot-log ranges that could span a mint WARN; (2) credentials reach consumers by FILE PATH reference (`api_token()`-style readers), never by value in a scenario, report, prompt, or chat; (3) any credential found in a transcript is treated as burned and rotated/deleted at the next lawful moment; (4) filed returns redact-and-document rather than preserve leaked values verbatim.

## 2026-07-26 | Category: process / program-hygiene | Source: the no-serve-path seam autopsy (v38 beat 7) — L4: design-doc intent needs an OWNER ROW
**Discovery:** Doc 13 §3.2–§3.3 ("the SPA is served by Javalin at /dashboard/") sat un-implemented for a month while every party's mental model marked it done: the core lane stopped at the REST API, the FE lane stopped at the Vite build + mocks (`npm run dev` forever; the D-2 no-route-to-Pi environment class masked it), and the build file's own comment asserted the serving as if it existed.
