## §1 — The rules

### R2.2 — NEVER (first; IR-210; RET R2.2)
**Rule.** No deleting path — a sweep, a per-type override (D04 `:196`), a priority tier or §6.5's emergency order (D01 `:833–840`) — deletes: (1) the registry's four types `device_registered`, `entity_registered`, `device_removed`, `capability.added` (`L/RegistryProjectionSubscriber:62–66`; `E/EventTypes:338`); (2) a command and its terminal: `command_issued` and its `command_result`, `state_confirmed`, `command_confirmation_timed_out` (`E/EventTypes:56`, `:62`, `:79`, `:65`); (3) the newest `state_baseline`. Membership is by TYPE, never priority.
**Why.** The registry rebuilds each boot from its four types (`HSC:617–648`); two are NORMAL (`Z/ZigbeeAdoptionSlice:391`, `:450`): 90-day tier retention or D01 `:839` empties it. The timed-out terminal is DIAGNOSTIC (`A/StandardPendingCommandLedger:899–900`) beside a NORMAL `command_issued` (`REST/IssueCommandEndpoint:216`): stripped, the command reads DISPATCHED (RET R2.3's inference from `A/StandardExplanationService:90–92`). ≈ 110 MB/yr at 200 commands/day.
**Touches.** R2's predicate; D01 `:842`; D04 `:196–207`. **Verified by.** IR-210's test: a 7/90/365 sweep on a fixture store keeps the registry and a timed-out command's ending.

### R1 — version, upcaster, degrade (RET R1; AUD §3: ACCEPTED)
**R1.1** The `schema_version` is the TYPE's: the publisher stamps one `currentVersion(type)` kept beside the registry; `EventDraft` loses its free version (or a mismatch fails the append under test). *Why:* 26 `new EventDraft(` sites in 18 files pick it (AUD §2.2) — `command_issued` from two constants (`REST/IssueCommandEndpoint:89`, `A/StandardActionExecutor:111`), literals at `Z/ZclIngestionUnit:936`, `S/ProductionDerivationRule:131`; `P/EventTypeRegistry`, `E/EventType` hold none.
**R1.2** ANY change to a type's encoded JSON — a key added, removed, renamed or retyped, or a value's meaning changed — bumps it by one, with the `v(n)→v(n+1)` upcaster and the golden fixture in the same commit. A version's SHAPE is its class's component set as the canonical instance encodes it, never a row's key set (`NON_NULL`, `P/PersistenceObjectMapper:107`). A change the old JSON cannot express stays a new type (D01 `:360`) or a DEFINED degrade (AMD-52, `P/EventPayloadCodec:166–181`). *Why:* D01 `:359` bumps additive changes; J3 T-B wrote its eighth component (`E/AutomationCompletedEvent:69`) at v1 (`A/StandardRunManager:119`, `:784–785`), the old-row default Jackson's zero-fill (`P/PersistenceObjectMapper:102–111`); the rig's 1,596 v1 rows have five keys (AUD §2.1). First use, IR-214: `automation_completed` v2 + an idempotent `v1→v2` (absent `skipped_unavailable` → 0) over both v1 shapes.
**R1.3** Upcasting is read-side, in the codec between registry lookup and typed read (`P/EventPayloadCodec:164` → `:184`): `PayloadUpcaster { String eventType(); int fromVersion(); JsonNode upcast(JsonNode) }` — pure, chained, lazy (D01 `:361–363`), keyed `(event_type, schema_version)`, wired by the composition root, no `ServiceLoader` (as `core/device-model/…/AttributeValueUpcaster:14–15`); chain completeness is a unit test, not a boot check; AMD-47's value upcaster stays the inner, later stage (ibid. `:30–33`). *Why:* none is wired (`P/EventPayloadCodec:55–56`); cost, one `JsonNode` parse per old-version read.
**R1.4** An unknown version degrades, never fails the boot: `> current` is read by the current class (INV-ES-07; `P/PersistenceObjectMapper:108`), degrading on failure; `< 1`, a chain gap or a throwing upcaster → `DegradedEvent` with the raw bytes. A core projection given a `DegradedEvent` of a type it consumes skips, counts, marks that SUBJECT DEGRADED and goes on (D01 `:861`). *Why:* narrows D01 `:367` to the subject; replaces the "halts" of `E/DegradedEvent:13–18`. Today (RET §6 left it unread): the codec clamps `< 1` only for its fallback (`P/EventPayloadCodec:148`); the registry and recovery-card projections skip with a warn, uncounted (`L/RegistryProjectionSubscriber:293–298`, `S/RecoveryCardProjection:384–386`); the state projection has none: its catch-all bumps `stateVersion` and `lastUpdated` for an ENTITY-subject one (`S/StateProjection:517–519` → `:971–984`).
**Touches.** The 26 sites; `P/EventPayloadCodec:143–196`; those three projections; D01 `:359–367`. **Verified by.** IR-211 (RET §3): T-G2 `currentShapeIsPinned` (catches J3 T-B), T-G1 on `v1.json` + `v1-tb.json`, T-G3 chain, T-G4 immutable, T-G5 `unknownVersionNeverThrows`; R1.4's arm: a test no source names (UNKNOWN).

### R4 — clock (RET R4, §4; AUD §3; IR-212)
**Rule.** Clock quality is a SYSTEM event, never a column or payload field: `clock_status { synchronized, wall_minus_head_ms, step_ms? }` at boot before the first device event (synchronized ⇔ `/run/systemd/timesync/synchronized` exists) and, after an unsynchronized boot, at the first sync (a 30-s tick), `step_ms` = Δwall − Δ`System.nanoTime()`. Readers order by `global_position`; rows between an unsynchronized and the next synchronized mark are "time approximate": flagged, kept out of time-window lookups (K2 falls back to its type scan, `A/StandardExplanationService:103–108`), aged from the closing mark; a ULID's time is identity, never order.
**Why.** Nothing reads clock state (0 hits: `NTPSynchronized|timesync|timedatectl|adjtimex`); the unit waits only for `network-online.target` (`distribution/systemd/homesynapse.service:17–18`); `ingestTime` is the append clock (`E/EventEnvelope:42–51`); `global_position` is the order (`HSC:630–631`). After a cut that takes the router the hub boots ≈ D behind (systemd ≥ 250 assumed; the rig's unread). ≈ 2 rows per outage, no migration; `After=time-sync.target` rejected: the hub must run offline.
**AMD-53, checked.** Activity times are `eventTime ?? ingestTime` (`S/StateProjection:874–884`), a report's `eventTime` the same clock (`Z/ZclIngestionUnit:937`): interval rows carry approximate times, which R4 flags; AMD-53 stands.
**Touches.** `E/EventTypes` (+`clock_status`); the boot in `HSC`; the grader's whitelist; the explain projection. **Verified by.** IR-212 (type, fixture, boot check, tick); a desk boot with the sync file absent, then present (proposed here).
