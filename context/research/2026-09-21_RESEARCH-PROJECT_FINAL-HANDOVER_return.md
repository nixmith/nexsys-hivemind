## §6 THE PROMPT DOCTRINE — how the hub writes a prompt that returns research

The Project answers the question it is asked at the depth the frame allows. A vague prompt returns a survey; a prompt that supplies the objects, the conjecture, the falsifier and the shape returns a theorem or an honest "not provable from this frame, here is the gap". Ten rules, then templates, then two worked openers.

### 6.1 The anatomy of a research prompt (ten parts, in this order — long material first, the question last)

1. **The state line** (one line; re-derived from disk at send, never from memory): `Date: <YYYY-MM-DD> (CT). Tree: core <sha> · hivemind <sha> · docs <sha> · bench <sha> · skills <sha>. Watermark AMD-<n>. Register: C-001..C-00n live. Closure counter: <k>/20.` Missing it makes the return ASSUMED-STATE — the Project says so, correctly.
2. **The knowledge line, with paths:** `Knowledge to lean on: K-04 §2.1/§2.5 (/mnt/project/K-04_evidence-floor_formal-model_v0-1.md), K-05 P-01 (…), K-14 B-2 (…).` Name the file and the §; the Project reads by path. Attach a file only when the conversation must audit it end to end.
3. **The not-checkable line:** which claims the K-set cannot verify (the plan of record; the counter; EXT-REVIEW-1; anything at source not in the companion). Without it the Project grades our state from K-08 alone and over-refutes.
4. **The frame excerpt:** paste the K-04 definitions the question's objects come from (§2.1 the alphabet Σ_c/Σ_u/Σ_o and the device contract ρ_d / envelope ε_d; §2.2 the log; §2.3 the actuation chain; §2.4 the lattice g0–g5 and p_c; §2.5 the kernel; §3 the independence principle in play; §4 the operator in play). The Project must prove against the frame's objects, not against a re-definition it makes on the fly. If the frame's definition is inadequate, the return says so as a finding — that is a K-04 field move, and valuable.
5. **The source companion:** `<source_companion>…</source_companion>` — the exact excerpts at HEAD the question turns on (file:line spans, DDL, enum bodies, doc §§, the B-row from K-14, the ADR row). The companion outranks knowledge and memory; say so in one line. A companion is never summarized inside the fence.
6. **The ancestors line:** the K-05 row's Ancestors, tiered from K-07 ([V] vs UNVERIFIED), with the instruction: *instantiate or extend — say which; if a published result already states the theorem, the return's job is to show the instantiation and mark the P-row for KILL or re-cut.*
7. **The charter block, in the charter form:** the id · **the question as a conjecture with hypotheses** (never "explore", "assess", "survey") · the scope fence (what is in; what is out; web policy) · the return cap · the instrument, tensed · **the refutable-by** (what one citation or one measurement would do to the result) · **what "done" moves** (the K-05 field by name) · Research ON/OFF.
8. **The resolution criterion:** what the return must contain to count — for a theorem: definitions consistent with the frame, the statement with hypotheses, a proof or a proof sketch with every gap named, the counterexample search (what was tried), the relation to each ancestor (instantiated / extended / orthogonal), the instrument that would test it on our system, the register-shaped sentence it would license (D5 form; never outward), the crosswalk lines for K-07, the census.
9. **The shape and the cap:** return in the K-12 shape (§0 card first; two lines per source; every dated fact with its URL and access date; every finding with its refutable-by; the census by tier); the cap in KB; a proof-bearing return may carry an appendix section after the card.
10. **The question, one, last** — one sentence that an answer either satisfies or does not.

**Sizing.** A theorem charter: 25 KB cap, a 40 KB appendix allowed for a full proof; a measurement-protocol charter: 15–20 KB; a formal-statement charter (one P-row field): 10–12 KB; a currency scan: 15 KB, deltas only; an adversarial review: 15 KB. One question class per conversation; the serial spine means one theorem in DESK at a time. Effort always at the highest setting. Research OFF unless the charter is a scan.

### 6.3 Template — the measurement-protocol charter (a bench row's design; never a number)

Same head; the charter block asks for: the quantity and its estimator; the pre-registered threshold (the kill or the bound) with the reasoning that fixes it before any measurement; the instrument (the bench scenario, the card, the fleet, the nights × runs); the variance methodology (SP-4: pinned governor, repetitions, bands, rig scope — n=1 rig stated); what would make the number unpublishable (a missing band; a copied count); the sentence the number would license in the D5 form with its scope fence; the refutable-by. **Question (one, last):** "Write the protocol so that a lane can build the row from it without asking a question, and state the threshold this protocol pre-registers." Research OFF. Cap 15–20 KB.

### 6.4 Template — the currency / prior-art scan (Research ON)

Head as above but the knowledge line names K-03 §2 as the baseline and K-09 §2.3 as the must-not-claim list; the companion is K-08 §0 pasted from the live register; the fence is *primaries, fetched, dated, URL'd; deltas only against the baseline*; the resolution criterion is per item: what changed · the two lines (crosswalk · refutable-by) · which §7 tripwire it touches · which fragment class it adds · whether any P-row's "Unclaimed" line is now claimed (then that row's KILL candidate). Cap 15 KB. **Question (one, last):** "What changed since <baseline date> that moves a K-03 row, a tripwire, or a P-row's Unclaimed line — and nothing else."

### 6.5 Template — the formal-statement charter (one P-row field)

Head as above; the ask is narrow: move one field of one P-row — Statement (a conjecture made precise), Ancestors (a tiered list), Unclaimed (a dated search re-run), Resolution (what counts), Instrument (tensed at HEAD via the companion), Refutable-by, Status — in the problem-register format (the skill's `references/problem-register-format.md`). Cap 10–12 KB. **Question (one, last):** "Return the new value of P-nn.<field> with the evidence that licenses the move, and nothing that moves another field."

### 6.7 Anti-patterns (each has produced a survey where a result was wanted)

"Explore / assess / survey / discuss" as the verb · a question with no conjecture · no frame excerpt (the Project re-defines the objects and proves something adjacent) · no companion for an instrument at source · no refutable-by · no "what moves" · a count or a tense in the premise ("its three rows"; "the hash-chained log") · two questions in one conversation · a return cap that forbids the proof · Research ON for a desk charter · a missing state line · asking the Project to grade our own state without saying what it cannot check · asking for a number (it will make a protocol; only the bench makes numbers) · asking for a recommendation without the words it would gate (it will escalate — correctly).

### 6.8 What a good return looks like, so the hub can tell at the bytes

§0 card first with the answer in one paragraph · every quoted line with file and line · premises verdicted before the work · the census by tier with [VERIFIED] / [REPORTED] / [INFERRED] / [VERIFIED-by-absence] counts · the proof (or the protocol, or the field) in the body with each step's dependency named · a "what was refuted or corrected in our own framing" section (the returns have been finding one item each — keep it) · two lines per source · the UNVERIFIED list · the words in the H10 form only where an act is gated · `RETURNED <path> <bytes>` as the last line.

## §7 Intake doctrine for mathematical returns (the addendum to layer 2)

When a return carries a theorem, a bound or a protocol, layer 2 is not a grep — it is a re-derivation. The hub: (1) checks every definition in the return against the K-04 § the prompt pasted, naming each divergence (a divergence is either the return's error or a K-04 field move — decide which, with the frame's §9 refutable-by in view); (2) re-derives each proof step it can, marks each it cannot as UNVERIFIED-BY-THE-HUB, and never lets a step it could not re-derive license a field move; (3) runs the counterexample search itself for one class or one device model (the cheapest attack); (4) checks the ancestor claims — "instantiated" means the cited theorem's hypotheses hold in our setting without extension; "extended" means the return added a hypothesis or an object — and re-reads the cited work at the tier K-07 gives it (an UNVERIFIED ancestor licenses nothing); (5) checks the novelty against K-09 §2.3 and the P-row's dated Unclaimed line, and re-runs that search once (the line expires); (6) commissions the adversarial review (§6.6, Opus 5) before any Status moves past DESK; (7) moves exactly one K-05 field per finding, dated, and tenses the instrument at HEAD; (8) writes the register-shaped sentence the result would license only as a DRAFT in the D5 form — nothing mints, nothing is outward, and a theorem about our own system is TRUE-TODAY only when a bench row has shown its hypotheses hold on the card. A number in a return is a protocol's example, never a measurement; only the bench makes numbers, with SP-4's bands.
