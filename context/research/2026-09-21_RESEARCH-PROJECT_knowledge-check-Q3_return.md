# The grade of a change-triggered witness (g3) and the coincidence bound — return

## §0 Card

**Outcome.** A change-triggered witness report is grade **g3** in the frame's verdict lattice (K-04 §2.4, file line 79). It removes the coincidence bound because that bound, p_c(W, T_d), is the probability that the device's report *timer* expires inside the confirmation window W — an event that occurs whether or not the command had any effect — and a change-triggered report is not generated by that timer: it is generated by a value transition. If the command had no effect and nothing else moved the attribute, a timer report still lands in W with probability p_c, and a change report lands there with probability zero, for every W and every T_d. The (W, T_d) term has nothing left to multiply.

## §2 Why g3 removes the bound

**2.1 What the bound measures.** p_c is the chance that a matching report lands in W when the command did nothing. A truthful, in-order report can match under that null in two ways — the value already satisfied the Expectation, or something else moved it — so [INFERRED]:

```
P(matching report in W | command had no effect)
   = 1[pre-command value already satisfies the Expectation] × P(report timer expires in W)     ← p_c(W, T_d)
   + P(another cause moves the value to a satisfying one inside W, and it is reported)          ← the residual (§3.1)
```

The indicator is 1 when the command re-asserts the current value, when a tolerance band already contains the old value, or when the hub has no usable prior record. That is the same-value case, and it is why K-05's P-04 conjectures that silent failure is not diagnosable there: "with only periodic same-value reports f is not diagnosable (indistinguishable from success + coincidence)" (K-05:61) [VERIFIED·K]. The figures the frame quotes — "~1.7 % at 5 s / ~10 % at 30 s at ~5 min" — come from the L-E return, which is not in the knowledge set; this session re-derived the arithmetic (§3.3), not the source [REPORTED].

**2.2 The mechanism, at the standard.** ZCL r8 §2.5.11.2 lists the conditions that generate a Report Attributes command.
- *Periodic* (§2.5.11.2.1, printed lines 2932–2934): a report is obliged when "the time that has elapsed since the previous report of the same attribute" reaches the configured maximum reporting interval. The input is a timer; no command, and no value, enters the condition. [VERIFIED]
- *Change* (§2.5.11.2.2, printed lines 2936–2940; §2.5.11.2.3, printed lines 2942–2948): for discrete types, any change of value obliges a report; for analog types, a report is obliged once the value has moved by at least the configured reportable change, measured from the last reported value. Both are throttled by the minimum reporting interval. [VERIFIED]
- The on/off example rests on the discrete clause: Table 3-45 lists OnOff (0x0000) as type bool with access RPS, and §2.5.11.2.2 names logical types among the discrete ones. [VERIFIED]

So the two witnesses come out of two different clauses. With no effect and no other cause there is no transition, the change clauses never fire, and the probability of a change report is zero whatever W and T_d are. In §2.1's terms: a g3 witness is one for which the log shows the indicator is 0 — the last recorded pre-command value did not satisfy the Expectation and the witness does — so p_c is multiplied by zero. [INFERRED from the two VERIFIED clauses]

**2.3 The same argument in P-03's vocabulary.** Ramdas, Grünwald, Vovk and Shafer define an e-variable for a null P as "a nonnegative random variable E such that E_P[E] ≤ 1" (§2.1; the subscript is the null), and observe in the same paragraph that against a single null a unit bet is a likelihood ratio [VERIFIED]. It follows that a g2 witness, whose null probability is p_c, yields a likelihood-ratio e-value of at most 1/p_c — 60 at (W = 5 s, T_d = 300 s), 10 at (30 s, 300 s) — so one g2 witness cannot cross a 1/α threshold for any α below p_c. A g3 witness's null probability is the residual term, which has no T_d in it; its e-value is bounded by the reciprocal of that residual, which §3.1's census would measure. That is the content of K-05:49's rule — stop at g3, accumulate otherwise. g4 lifts the bound by a different route: an independent witness multiplies null probabilities. [INFERRED]

*What this does to the frame:* confirms §2.4's ordering of g2 below g3 at the mechanism, for Zigbee. It also says what g3 is a statement about: the absence of the timer as a sufficient explanation — not the presence of the command as the cause (§3.1).

## §3 Four qualifications the frame's sentence needs, and a transport note

**3.1 g3 removes the timer term, not every coincidence.** The frame's own alphabet contains the other causes: "Σ_u = uncontrollable events (occupant actions, device-autonomous changes, failures, radio weather)" (K-04:44) [VERIFIED·K]. An occupant pressing the device's button, a bound remote, or a second controller can produce the expected transition inside W; the resulting report is change-triggered and matching, and the command had no part in it. The residual is roughly (rate of such transitions to the expected value) × W; it does not depend on T_d, and nothing in the mechanism makes it zero. K-04:79's gloss — causal, not coincidental — is therefore stronger than the mechanism supports. [INFERRED]
*Refutable-by / candidate census:* N commands suppressed at the adapter (failed by construction) while an operator toggles the device on a schedule the run does not know; count matching change reports inside W. A nonzero count confirms the residual; zero across a designed exposure bounds it (the rule-of-three bound K-05 already lists among P-03's ancestors).

**3.2 Change-triggered is a classification the hub makes; the wire does not say.** A ZCL attribute report is three fields — identifier (2 octets), data type (1), data (variable) — per §2.5.11.1, Figure 2-24 (printed lines 2903–2921), under a header of frame control (frame type · manufacturer-specific · direction · disable-default-response · three reserved bits), manufacturer code, transaction sequence number and command identifier (§2.4.1, Figures 2-2 and 2-3, printed lines 2365–2392). None of these encodes why the report was generated; a keyword scan of the chapter-2 general-command clauses for reason, cause and trigger found no such field. [VERIFIED for the field lists]
Two tests are available from the log [INFERRED]:
- *value-delta* — the witness satisfies the Expectation and the last recorded pre-command value did not;
- *off-schedule* — the witness arrived sooner after the device's previous report of that attribute than the device's kept cadence (ε_d's lower bracket) allows, with no rejoin or reconfiguration in between (§2.5.11.2.1 leaves unspecified when a freshly configured device sends its opening report).
They fail in opposite directions under report loss. Value-delta can over-grade: if an earlier change report was lost, a timer report in W looks like a change, and the bound comes back as P(stale record) × p_c. Off-schedule can under-grade but not over-grade: a lost report makes the observed gap longer, never shorter, so a timer report still reads as on-schedule. The grade law (stated grade ≤ evidence grade) is met by the conjunction.
The design digest suggests the seam for the value-delta half exists in the event model — "`state_reported` (integration; the atom; no previous value) → `state_changed` (projection; old/new/`triggered_by`)" and "`match_type` ∈ {exact, within_tolerance, enum_transition, any_change}" (K-11:32) [REPORTED — digest; paste Doc 01 §3.8 and the ledger source as a companion before relying on it].
*Refutable-by:* a ZCL revision or a manufacturer extension that marks report cause on the wire (then the classification is the device's, not ours); or a captured trace in which a device emits a maximum-interval report sooner than its kept cadence's lower bracket after a report the hub received, with no rejoin or reconfiguration between them.

**3.3 The formula: for a timer, the term is linear, and the exponential sits below it.** §2.5.11.2.1 makes the periodic report a fixed-interval renewal, not a memoryless arrival. With the command time independent of the timer's phase, P(timer expires in W) = min(1, W/T_d). The frame's 1 − e^{−W/T_d} is the memoryless-arrival value; since 1 − e^{−x} < x for every x > 0 it is the smaller of the two everywhere [INFERRED · computed this session]:

| W (T_d = 300 s) | min(1, W/T_d) | 1 − e^{−W/T_d} | ceiling on a g2 e-value (1/p_c, linear form) |
|---|---|---|---|
| 5 s | 1.667 % | 1.653 % | 60 |
| 30 s | 10.000 % | 9.516 % | 10 |
| 300 s (W = T_d) | 100 % | 63.2 % | 1 |

Both forms round to L-E's figures at the two quoted points, so nothing quoted so far is wrong; for a quantity named a bound and disclosed as an error bar, the linear form is the conservative one. Neither form holds when command times are phase-locked to the device's timer: an automation triggered by that device's own report of the same attribute puts the next timer expiry about T_d away (the term goes to 0 for W < T_d), and a wall-clock schedule can ride the expiry (the term goes to 1). That is what ε_d and P-03's per-device rule are for. ZCL §2.5.11.2.5 (printed lines 2951–2976) also lets a device shorten — never lengthen — its maximum interval to share timers [VERIFIED], which supports K-04 v0.1's own alignment: "the g2 bound is written p_c(W, T_d) as in K-05 (v0 wrote ρ_d, the declared contract, where the cadence is meant)" (K-04:16) [VERIFIED·K].
*Refutable-by:* bench inter-report gap histograms, per device, that are exponential rather than concentrated at one interval.

**3.4 Where g3 cannot exist, and what that does to the S3 kill metric.** No change report is generated when the command re-asserts the current value (no transition), when an analog move is smaller than the reportable change (§2.5.11.2.3), or — as far as the hub can count on it — when the device's reporting configuration could not be verified (the downgrade posture; K-06 Addendum 2's log lines `verified=0 degraded=1` and `outcome=best_effort`) [INFERRED from VERIFIED clauses and VERIFIED·K log lines]. In the other direction, a maximum reporting interval of 0x0000 (with the minimum not 0xffff) switches periodic reporting off while change-based reporting stays operational (§2.5.7.1.6, printed lines 2706–2707) [VERIFIED]: p_c is then zero by configuration, at the price of the periodic report itself, which is also the device's routine sign of life on this channel [INFERRED].
This bears on the frame's own falsifier — "the grade law cannot be met on real devices because change-triggered reports (g3) are too rare to ever lift g2's coincidence bound" (K-04:201, item 4) — and on S3's provisional kill line, "fewer than 20 % of confirmations on the fleet arriving as change-triggered reports" (K-13:89; a placeholder the file marks as never quoted outward) [VERIFIED·K]. Counted over all confirmations, a re-assertion-heavy automation mix lowers the g3 share without saying anything about evidence quality: for a re-assertion, g2 is the ceiling by construction and the causal question is moot, because the state already held. The share over state-changing commands is the quantity the falsifier is about. [INFERRED]
*Refutable-by / candidate census:* the g3 share on the fleet computed over both denominators; if the two agree within the run's variance bands, this qualification is idle.

**3.5 Transport note (P2).** In Matter 1.2, a subscription's reports carry the delta changes since the previous report, and the publisher keeps the subscription alive at the maximum interval with a report that §8.6.2 describes as a "report with no data or events" (§8.5; §8.6.2, p. 445) [VERIFIED for 1.2, dated 2023-10-18; later releases not checked]. One vendor's SDK documentation describes the same behaviour as a liveness check sent when no attributes have changed [REPORTED — vendor documentation, Silicon Labs]. On that contract no timer-driven *value* report exists, so a subscription produces no p_c term at all; a same-value witness would need an explicit read. For P2 — verdict semantics defined on (ρ_d, ε_d), never on the radio — the consequence is that ρ_d needs a field saying whether the periodic report carries values; with that field, the g2/g3 semantics stay equal across the two transports [INFERRED]. For our own system Matter is ASPIRATIONAL (K-09 §5, H7: Zigbee is the shipped adapter) [REPORTED].

## §5 What was refuted or corrected in our own framing

1. K-04:79, causal, not coincidental → g3 removes the timer as a sufficient explanation; a Σ_u residual remains and is not a function of T_d (§3.1).
2. K-04:86 and K-05:49, p_c ≈ 1 − e^{−W/T_d}, named a bound → under ZCL's fixed-interval timer and uniform phase the term is min(1, W/T_d); the exponential form sits below it; neither holds under phase-lock (§3.3).
3. Change-triggered, used as a property of the report → it is a classification made by the hub; value-delta alone lets the bound back in, scaled by the probability of a stale record; the conjunction with the off-schedule test is what the grade law needs (§3.2).
4. K-13:89's provisional kill line → its denominator should be state-changing commands, or it measures the automation mix (§3.4).

None of the four moves a construct: g3's place in the lattice, the grade law and P-03's conjectured stopping rule stand as written.
