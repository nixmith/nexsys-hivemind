## §0 The first page

**The five findings that matter most** (ids point into §3 and Appendix B; every line is Fact unless marked).
1. **The promise fails at the one moment it matters: a power cut, not a crash.** `journal_mode = WAL` then `synchronous = NORMAL` on every connection (re-read by this session: `homesynapse-core:core/persistence/src/main/java/com/homesynapse/persistence/DatabaseExecutor.java:446–447`, `connectionPragmas()`), per-INSERT autocommit, the WAL checkpointed only at graceful stop (`SqlitePersistenceLifecycle.java:44–46` javadoc), and publish-`command_issued`-then-dispatch. SQLite: "a transaction committed in WAL mode with synchronous=NORMAL might roll back following a power loss or system crash" (https://sqlite.org/pragma.html#pragma_synchronous, read 2026-10-12). So the log can read "never issued" while the relay already switched. The WAL spike tested SIGKILL only (`spike/wal-validation/kill-driver.sh`). *Inference, H.* (F1)
2. **"Did the device confirm" is at half strength, and the first household's stick may be refused at boot.** The adapter never consumes the APS `messageSentHandler` (no 0x003F handler anywhere; `…zigbee/EzspCoordinatorProtocol.java:≈147`, `APS_OPTIONS_RETRY_ROUTE_DISCOVERY`), so "never left the mesh", "acted but did not report" and "reported a different value" collapse into one `unconfirmed`; idempotent commands cannot confirm at all (F25, F26). EZSP v13 only — v14 throws `PermanentIntegrationException` (`EzspCoordinatorProtocol.java:74–87`) while the same SKU now ships v14 (`nexsys-bench:corpus/coordinators/sonoff-dongle-plus-mg24_efr32mg24_ezsp.md:28, 41, 45`) (F28).
3. **The record has no product-level backup, no restore, no replacement path, and no retention rule.** `createBackup`/`restoreFromBackup` throw `UnsupportedOperationException` (`SqlitePersistenceLifecycle.java:52–55, 480–494`); `MaintenanceService` has no implementation; the rig store hit 829 MB / 1.65 M rows in ≈ 2 months (`nexsys-hivemind:context/handoff/pm-handoff.md:34`; re-read `HomeSynapseCore.java:623`); the NWK frame counter is not persisted on the Pi — a re-form writes `networkKeySequenceNumber = 0` and the counters live in the stick's NVRAM (re-read: `EzspCoordinatorProtocol.java`, `encodeInitialSecurityState` / `resumeFromNvram`) — so a stick swap re-pairs every device. (F2, F19, F29)
4. **Three one-way doors close in the next five weeks with their instruments unsigned or unwritten:** the LICENSE flip (Nov 3–9) on a proprietary tree (`homesynapse-core:LICENSE:1`; `README.md:407–412`) with the IP assignment and the OA consent both "DRAFT — NOT EXECUTED" (`legal/NexSys-LLC/2026-08-28_DRAFT_*`); the event envelope with a `schema_version` column and no upcaster (`EventPayloadCodec.java:52–55, 166–186`) before the first household writes an event (Nov 19); the frozen v1.1 API with no machine-readable artifact (`specs/openapi/` holds `.gitkeep`) before P6 publishes it. ### Code and architecture
**F1 — Durability at the one moment that matters: `synchronous=NORMAL` + publish-then-dispatch means a power cut can leave a switched relay with no `command_issued` row.**
**Fact** — `connectionPragmas()` emits `journal_mode = WAL` then `synchronous = NORMAL` on every connection (re-read by this session: `homesynapse-core:core/persistence/src/main/java/com/homesynapse/persistence/DatabaseExecutor.java:446–447`; the WAL is checkpointed with `wal_checkpoint(TRUNCATE)` only at graceful stop, `SqlitePersistenceLifecycle.java:44–46`); SQLite documents that "a transaction committed in WAL mode with synchronous=NORMAL might roll back following a power loss or system crash" while "transactions are durable across application crashes regardless" (https://sqlite.org/pragma.html#pragma_synchronous, read 2026-10-12); appends are per-INSERT autocommit; no production code forces a WAL checkpoint (helper; the only `wal_checkpoint` mentions are javadoc). The automation executor publishes `command_issued` durably and a co-located LIVE subscriber then dispatches (`StandardActionExecutor`, helper). The WAL spike tested SIGKILL, not power loss (`homesynapse-core:spike/wal-validation/kill-driver.sh`). **Inference** — in WAL mode `NORMAL` survives a process kill but the last transactions can be lost on power loss before the next checkpoint (SQLite's own documentation; see §4 R2 prior art); a Pi on SD with no UPS loses *power*, not processes. So the log can read "never issued" while the relay switched — the explainability promise fails exactly where a lock or heater makes it matter. Confidence H (mechanism) / M (frequency). Horizon **pilot**. Impact: the product's one sentence. Cost now: small and freeze-safe to *measure* (a wall-pull trial on the bench Pi with a pre-registered expectation); the fix (`synchronous=FULL` on safety-relevant priorities, or a passive checkpoint after `command_issued`/`command_result`) is a one-unit Java change post-run. Cost now: one callback and one field on `command_result` (post-run Java; a vocabulary addition to a frozen API, so it should be designed before the pilot's records accumulate); later: a vocabulary change under live household data.

**F26 — Idempotent commands cannot confirm; the bench knows it and classifies it as cause `bench` rather than the product handling it.** **Fact** — reporting is reportable-change-gated (`Z/ReportingConfigurator.java:88`), so `turn_on` on an already-on device yields no edge, no `state_reported`, and a timeout; the grader's timeout-cause rule step 3 names this (`nexsys-bench:tools/verify72h/README.md`, "The cause of a timeout"); no read-back exists in the dispatch path, though the probe's ZCL exchange at `Z/ZigbeeIntegrationAdapter.java:999–1012` is the same mechanism. Confidence H. Horizon pilot (false "unconfirmed" on a household dashboard). Cost now: a conditional read-attributes read-back on timeout (post-run); later: a household learns to distrust the hero.

**F27 — Availability probes block the whole adapter: a tripped breaker on eight plugs stalls ingestion and dispatch for ≈ 80 s per sweep.** **Fact** — `evaluateAvailabilityTimeouts()` runs `pingBasic` synchronously on the 50 ms production thread with a 5 s timeout per device (`Z/ZigbeeIntegrationAdapter.java:835–849, :165, :192`); the tracker's comment admits the acceptance holds for N ≤ 2 simultaneously silent devices (`Z/StandardAvailabilityTracker.java:108–112`); timeouts are fixed constants "by design … the run's fleet is fixed" (re-read: `MAINS_PING_SILENCE` 60 s `:120`, `PROBE_MISSES_TO_DARK` 2 `:135`, `BATTERY_OFFLINE_SILENCE` 25 h `:142`; `EzspCoordinatorProtocol.java:92–96`); the same javadoc records SOAK-NIGHT-1 naming five plugs dark in ten hours "that were never gone", each at +65.1 s of silence, undone by the plug's own next report 69–73 s later — the fixed floor racing a 600-s reporting contract (`:92–99`). **Inference** — at 60 devices a power blip is minutes of a deaf hub, exactly when a leak sensor's report matters. Confidence H. Horizon the first 60-device home (2027). Cost now: async probe futures through the existing `submit()` (moderate, post-run); later: entangled with the frozen `probe_answered` events.

**F28 — EZSP v13 only; the same SKU now ships v14 — the first pilot household that buys a current stick is refused at boot.** **Fact** — v14 → `PermanentIntegrationException` (`Z/EzspCoordinatorProtocol.java:74–87`); the bench stick was frozen on EmberZNet 7.4.5.0 / v13 because that batch shipped it; the SKU's default ship is 8.0.2 / v14 (`nexsys-bench:corpus/coordinators/sonoff-dongle-plus-mg24_efr32mg24_ezsp.md:28, 41, 45`); Silicon Labs' current SDK ships Zigbee 9.1 (§5). Confidence H. Horizon **pilot** (the kit list, THE HORIZON C5). Cost now: the kit ships a flashed stick (a procedure) and the v14 dialect is characterized ("Wave-2", already named); later: every household's stick is a support call.

**F29 — A coordinator swap is not restorable: the NWK frame counter is not persisted and the EUI64 is never written.** **Fact** — a re-form writes `struct[34] = 0; // networkKeySequenceNumber` in `encodeInitialSecurityState` (re-read, the file's tail; the helper's `:2322`), while the normal path `resumeFromNvram()` is an EZSP `networkInit` against the stick's own NVRAM — the Pi holds no frame counter; the code names the gap ("closed later by the FRAME-CTR custody schema", `NetworkFormation.resume()` javadoc); the coordinator EUI64 is only read (`:361, :1917`); bindings point at the old EUI64 (`Z/EzspReportingOps.java:47–48`). **Inference** — a Pi swap with the same stick works; a stick swap or NVRAM wipe means every device re-paired by hand. Confidence H (Zigbee NWK freshness + binding semantics; not bench-verified). Horizon 2027. Cost now: persist the frame counter and write a custom EUI64 token at formation (post-run); later: a household-wide re-pair per stick failure. Pairs with F19.

**F30 — No mesh telemetry, no OTA, no groups; NCP tables sized for a bench.** **Fact** — `topologyScan()` throws `UnsupportedOperationException` (`Z/EzspCoordinatorProtocol.java:1497`); `NeighborTableEntry` is never produced; the only radio health data is last-hop LQI/RSSI per frame (`Z/LinkReading.java`); address table 16, end-device children 32, key table 12 (`:335–342`); no OTA cluster, groupId always 0 (helper grep). **Inference** — nothing can tell "the kitchen router died" from "the sensor died"; at 60 devices the address table forces constant lookups; lights at scale go per-bulb unicast. Confidence H. Horizon 2027. Cost: §4 R6.

**F31 — What a 72-hour PASS proves, and does not.** **Fact** — the grader proves bookkeeping invariants: every command reaches exactly one terminal, every run terminates, no CONFIRMED beside a failure, every event classifiable, vocabulary frozen, no config errors, zero pairing windows (`nexsys-bench:tools/verify72h/README.md`; `grader.py:251, 257–265`); soak numbers are informational only. It does **not** prove: that anything was confirmed (a window where every command times out `unconfirmed` passes); that availability verdicts were true (no ground truth); resource health (no RSS/CPU/disk/WAL line; `integration_restarted` is ambient-whitelisted, `grader.py:207–208`); mesh fitness (ten devices, `bench/scenarios/constants.yaml:70–88`); sleepy-device death inside the window (the 25 h rule); a DST edge; power loss mid-write. Rehearsal 1: 1.58 h, 2 commands, 4,391 events/h, 562 KB payload/h (`bench/corpus/runs/2026-09-28_rehearsal-1/report.md`) → ≈ 13.5 MB/day at ten devices, ≈ 80 MB/day at sixty (linear inference). **Opinion** — the right gate for *honesty*, the wrong gate for *radio fitness*. Keep it; add a minimum confirmed ratio per confirmable device, restart count = 0, a probe-answered ratio and a store-growth ceiling to the same grader (freeze-safe: the bench is not the core); and make the pilot households produce what the bench cannot — a device behind two hops, a stick-swap drill, a breaker-trip drill, operator-reported "it didn't do what I asked" incidents reconciled against `timeout_causes`.

## §4 R&D opportunities (ranked by leverage)

Leverage = (how much it moves the product's one promise or its moat) × (how hard it is to copy in a release). Lanes: **coder** (Claude Code cloud), **research** (Cowork), **math/science** (Nick's research project), **bench**. Prior art marked ★ is already in Nick's `Research Papers` folder (listed by this review).

**R1 — Deterministic simulation testing of the core, with power-loss fault injection.** *Problem:* 51 `Thread.sleep` in tests, no power-loss or disk-fault injection, the WAL spike tested SIGKILL only (F1, F10); yet the seams exist — `TestClock`, `SynchronousEventBus`, `FakeNcp`/`FakeSerialByteChannel` (`homesynapse-core:testing/test-support`, `integration-zigbee/src/testFixtures`), `WriteCoordinator` with a `ThrottledWriteCoordinator` fixture, `CoordinatorTransport{open,close,sendFrame,receiveFrame}` (helper). *Gain:* the only way to make "a load switched wrongly" and "the log says never-issued while the relay switched" (F1) *impossible* rather than unlikely; a mesh simulator behind `FakeNcp` tests F27 at 60 devices without a rig; every bus and ledger invariant becomes a property, not a 20-sample counter (F8). *Cost:* a torn-write layer under sqlite-jdbc (a VFS shim or a file-copy-at-random-offset harness — `spike/wal-validation/kill-driver.sh` is the template) and a scheduler that owns every thread; 3–6 weeks of coder time over Q1 2027. *Risk:* the simulator diverges from the real NCP; mitigated by replaying bench captures through it. *Prior art:* FoundationDB's simulation testing (Zhou et al., SIGMOD 2021); Jepsen; ALICE / "All File Systems Are Not Created Equal" (Pillai et al., OSDI 2014) for crash-consistency bugs; SQLite's "How To Corrupt An SQLite Database File" and "Write-Ahead Logging" docs for `synchronous` semantics; ★ Alpern & Schneider, *Defining Liveness*. *Lane:* coder, after the run; a research lane first (SIM-1, §6) to design the seams.

**R2 — Accrual (φ) failure detection for availability, and a suspicion level instead of a 5-s boolean for confirmation.** *Problem:* fixed constants by design — 60 s mains silence, 2 misses, 25 h battery, 3,200 ms per EZSP command, 5 s confirmation (`Z/StandardAvailabilityTracker.java:120, 135, 142`; `EzspCoordinatorProtocol.java:92–96`; `StandardCapabilities.java:53`); 37 % of S31 runs time out with no mechanism on record (F7); probes block the adapter (F27). *Gain:* availability becomes a per-device, per-class *level* learned from inter-arrival samples that already exist (`lastSeen`, frame counts); fewer false UNAVAILABLE/unconfirmed, and a structured record no incumbent keeps (§5: Z2M is a fixed 10-min ping). *Cost:* small code; the hard part is the *vocabulary* — a frozen API that says AVAILABLE/UNAVAILABLE must learn to say "suspected since". *Risk:* explaining a probability to a homeowner; keep the 25 h battery floor and a boolean surface over the level. *Prior art:* Hayashibara et al., *The φ Accrual Failure Detector* (SRDS 2004); Cassandra's and Akka's implementations; ★ Lamport 1978 for the ordering half. *Lane:* math/science (the estimator), then coder.

**R3 — Why-not provenance for "why didn't it fire?"** *Problem:* the condition side exists (`StandardRunConditionGate` publishes `automation_condition_evaluated`; `NonFiringExplanation.java`) but trigger non-matches are not recorded (`StandardTriggerEvaluator.evaluateMatches`, `:486–515`); HA now ships a `not_triggered` bucket (§5), so the lead is ≤ 12 months. *Gain:* the one explain question HA has not generalized, answered from a structured record instead of a 5-deep trace: "it did not fire because predicate P on event E was false, and here is the event that would have satisfied it". *Cost:* a bounded ring per automation (off the log — F2), a query in `StandardExplanationService`, an API addition (v1.2). *Risk:* volume if written to the log; keep it in memory with a periodic summary event. *Prior art:* Chapman & Jagadish, *Why Not?* (SIGMOD 2009); Herschel & Hernández, *Explaining missing answers* (VLDB 2010); Bidoit, Herschel & Tzompanaki, *Query-based why-not provenance* (EDBT 2014); Cheney, Chiticariu & Tan, *Provenance in Databases* (Foundations and Trends 2009). *Lane:* research (PROVENANCE-1), then coder.

**R4 — Formal models of the confirmation and availability state machines (TLA+/Apalache), checked against the simulator's traces.** *Problem:* the bus class closes on a 20-sample counter (F8); the ledger's modes (`tracked → confirmed | timed_out | superseded | expired_on_restart | invalid`, REPLAY vs LIVE, `StandardPendingCommandLedger.java:138–171, 503–575`) and the tracker's states (`{UNKNOWN, AVAILABLE, UNAVAILABLE}` × six reasons, `StandardAvailabilityTracker.java:291`; `AvailabilityReason.java`) are small enough to model; the restart classification (IDEMPOTENT / CONDITIONAL / NOT_IDEMPOTENT, `:561–575`) is the interesting liveness property. *Gain:* "replay cannot re-switch a load" and "a checkpoint never advances past an undelivered position" become checked properties an enterprise reviewer can read; the model becomes the spec for a Matter adapter (R8). *Cost:* 2–3 weeks for someone who has read ★ Baier & Katoen and ★ Huth & Ryan — Nick's coursework. *Risk:* the model drifts from the code; tie it to R1's trace checking. *Prior art:* Lamport, *Specifying Systems*; Newcombe et al., *How Amazon Web Services Uses Formal Methods* (CACM 2015); Apalache; ★ Alpern & Schneider. *Lane:* math/science (Nick), as a December course-adjacent project.

**R5 — A tamper-evident event log (hash chain + periodic signed checkpoints) an insurer or auditor could verify offline.** *Problem:* `chain_hash BLOB(32)` exists and is bound to `ZERO_HASH` on the single write thread (`SqliteEventStore.java:153–154, 530`; `README.md:318` is honest about it); the envelope byte is explicitly "chain-coverable" (`:140–149`). *Gain:* the §5 buyers who pay (property managers, enterprise reviewers) ask "can the record be altered?"; this is the cheapest sentence that distinguishes the record from a backup of a self-purging store. *Cost:* prev-hash read + compute on the write thread, startup verification in `DatabaseExecutor.start`, a per-hub signing key beside `.root-key` (F19 means the key custody must be designed with the backup path), an export format. *Risk:* retention/compaction (F2) must preserve chain verifiability — design them together; a hub-local key only proves "unchanged since signed", not "signed by an honest hub" without a relay-witnessed checkpoint. *Prior art:* Crosby & Wallach, *Efficient Data Structures for Tamper-Evident Logging* (USENIX Security 2009); Certificate Transparency (RFC 6962) Merkle structures; immudb/QLDB designs; ★ Anderson, *Security Engineering* (audit logs). *Lane:* research (LEDGER-1) then coder; the export format first.

**R6 — Zigbee mesh health analytics.** *Problem:* `topologyScan()` is a stub, neighbor tables never produced, only last-hop LQI/RSSI (F30); no `messageSentHandler` so APS delivery status is discarded (F25); NCP tables sized 16/32/12 (`:335–342`). *Gain:* "the kitchen router died" as a record; a fleet view (COMMERCIAL-1 §2.3) with something to show; the installer's first paid feature. *Cost:* ZDO `Mgmt_Lqi_req`/`Mgmt_Rtg_req` walks on a timer, the APS callback, NCP counter reads; storage off the hot log. *Risk:* chatty walks on a 60-device mesh; budget them. *Prior art:* Zigbee2MQTT's network map; the Zigbee specification's ZDO management clusters; Silicon Labs AN1233 (Zigbee security) and the EmberZNet counters API. *Lane:* coder, Q1 2027, after R2.

**R7 — An appliance OS: image-based A/B updates, a read-only root, a watchdog, signed artifacts.** *Problem:* two update paths, one with rollback, neither signed, two non-atomic `mv`s (F20); the watchdog is a seam with no transport (F6); no backup medium (F19); CRA/PSTI want a declared support period and secure update (F16). *Gain:* "an update that bricks homes" moves from *unlikely* to *impossible by construction*; fleet rollout becomes a channel, not a script. *Cost:* a custom Pi image (`build-image.sh` is the seed) on RAUC or Mender with a dual rootfs and boot-count confirmation; a signing key and a release process; one engineer-month. *Risk:* a second platform to maintain; mitigate by keeping the `.deb` for developers and the image for customers. *Prior art:* RAUC and Mender documentation; swupdate; Raspberry Pi's `tryboot` A/B mechanism; systemd `RuntimeWatchdogSec`; TUF (The Update Framework) for signing. *Lane:* coder (APPLIANCE-1 design first, research lane), Q1 2027; the token-leak and symlink-flip fixes are post-run units now.

**R8 — Hybrid logical clocks and a multi-hub merge order.** *Problem:* `logical_time`/`node_id` are reserved and bound 0 (`SqliteEventStore.java:527–528`); BUS-ORDER-1 orders by `global_position`, so a multi-hub merge needs a second order key through `ReplayDriver`/`TransitionCoordinator` (helper). *Gain:* the multi-site operator (COMMERCIAL-1 §2.4) needs one record across units; HLC makes the merged record causally consistent without a central clock. *Cost:* envelope fields, a merge path, a conflict rule; nothing before a second hub exists. *Risk:* premature. *Prior art:* Kulkarni et al., *Logical Physical Clocks* (OPODIS 2014); ★ Lamport 1978; ★ Kleppmann DDIA ch. 9. *Lane:* math/science note now (one page: what the envelope must reserve so R8 stays possible), coder in 2027-H2.

**R9 — Matter/Thread as a second radio path.** *Problem:* the core sees only `IntegrationAdapter{initialize,run,close,commandHandler}` and `CommandHandler.handle(CommandEnvelope)`; `ConfirmationPolicy` lives in `core/device-model` (good), but `Confirmability`, `DeviceProfile`, `ReportingPosture` are Zigbee-module types a second radio must re-derive (helper); Matter 1.6 standardizes device-side explanations and sensor histories (§5). *Gain:* the installer's "multi-vendor" ask; the confirmation record expressed over Matter's subscription/ack model is a stronger sentence than APS acks. *Cost:* a second radio device, CSA membership (~$7k/yr + $3k per certification, 2023 figures), a Matter SDK integration in Java (no mature one — a sidecar in C++/Rust is likely). *Risk:* a quarter of an engineer with no buyer yet. *Prior art:* the Matter specification (CSA); OpenThread; `python-matter-server` (HA) as a sidecar precedent. *Lane:* research (MATTER-1, Q1 2027: can the event model carry it without a schema change?); build waits for a buyer.

**R10 — A safety-controller (Simplex) layer for loads that heat, lock or pump.** *Problem:* a partial run (action 1 switched, action 2 failed) is the dangerous state and nothing compensates (helper, `StandardActionExecutor.java:97, 233–236`); the pilot excludes "anything that heats" (`OUTREACH-2…:38`). *Gain:* the only credible path to locks/heaters/valves — and the insurer's and property manager's question. *Cost:* a per-device envelope (max on-time, interlocks) enforced below the automation engine; a design, not a feature, in 2027. *Prior art:* ★ Sha et al., *The Simplex Architecture* (ACC 1998) and ★ *Using Simplicity to Control Complexity*; ★ Schneider, *Enforceable Security Policies*; ★ Ligatti et al., *Edit Automata*. *Lane:* math/science (Nick's own reading program), 2027.
