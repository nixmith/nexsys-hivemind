# RS-5 — plugins as the community wedge: evidence before adoption

## §0 What is already true (the lane does not re-litigate these)
- **The architecture already reserves the seam:** Doc 18 (`homesynapse-core-docs/design/18-extension-and-plugin-architecture.md`, LOCKED 2026-07-03). The question is NOT "can we do plugins" — it is SEQUENCING, positioning, and cost.
- **The layer thesis governs the frame:** `Substrate_Thesis_v0.md` (L0–L3; §11 precedence law). A plugin surface is where third-party code meets the trust boundary — the exact place the deterministic-floor thesis (D5 language law: the floor is MISSING from the field, not SUPERIOR) is either compounded or diluted.
- **The honesty program binds every public act:** no public sentence outside the register (H9) · no community/beta before R-10 + the WRITTEN privacy posture · no public brand use before G-2. A plugin-community wedge is a POST-gate act; the pre-gate work is design + evidence.
- **Strategy v1.1 §3.6:** every week moves ≥1 outward-chain act. This charter exists so the wedge choice is made ON EVIDENCE the week the gates open, not improvised.

## §1 The questions (falsifiers first — the return LEADS with what would kill the pivot)
1. **The dilution falsifier:** does third-party plugin code inside the trust boundary structurally undermine the L1 claim ("the harness enforces; the model only proposes") and the privacy posture? What isolation does Doc 18 actually provide vs what a public SDK must promise? What did HA's/SmartThings' plugin security incidents cost them? If this can't be fenced, the pivot dies here — say so first.
2. **The API-freeze debt falsifier:** a public plugin SDK freezes surfaces pre-1.0. Enumerate exactly which Doc 18 seams would freeze, and what the M-milestone cost of stabilizing them is vs the current MVP path. If the freeze debt eats the fall, the wedge is later, not now.
3. **The ecosystem evidence:** what do the living ecosystems actually look like — HA integrations + HACS, SmartThings Edge, Hubitat, Homey — contributor counts, what motivates the FIRST 20 contributors, time-to-first-plugin, moderation/safety burden on a solo founder. Primary sources; numbers dated; instrument-limit disclosed.
4. **The wedge comparison:** plugin-SDK-first vs explainability-hero-first vs verification/bench-as-product ("the measured confirmed|unconfirmed moat") as the community's entry story. Which produces honest register sentences SOONEST? Which compounds the substrate bet under model progress (the thesis test)?
5. **The MHS adjacency:** does the MHS datum (strategy/2026-08-28_MHS-datum_first-read.md + addendum) change what "plugin" should even mean here (device-class adapters vs automation packs vs agent-facing extensions)? The borrowed-vocabulary rule applies — check the adjacent bodies before claiming a vacuum.
6. **Register readiness:** for each branch, draft the two or three sentences the register could HONESTLY mint at wedge-launch, with refutable-by shapes. A wedge that cannot produce honest sentences is marketing air and fails H9.
