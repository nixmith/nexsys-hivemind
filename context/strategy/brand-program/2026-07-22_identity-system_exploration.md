# Identity-System Exploration (all name-bearing items: EXPLORATION — R-1 HELD)

## 0. The design brief this exploration answers

The identity must render the trust thesis visible before a word is read: **infrastructure-grade software presented with consumer-grade calm** (the north star), executed in the W-3 reference class (documents like Stripe, feels like Apple, Oracle-Redwood gravitas, Framework's ownership ethos as counterweight), for the W-1 launch audience (prosumers/HA refugees) without encoding "hobbyist" (W-3a maturation arc). Nick's recorded taste anchors it: **bold wordmark + a single device**, evolved past the draft logo's critiqued elements (scribble/gradient/grid texture, and note the locked rule already on the books: *no gradients in logos*, visual-design-reference §1.1.6 — the draft's gradient was out-of-spec before taste even entered it).

Everything below is designed **name-agnostic first**: the system (color, type, spacing, motion, device-mark logic) is built so the ruled name drops in. Only the letterform work is name-bound, and each name-bound item carries its swap cost.

## 1. Wordmark directions (3) — EXPLORATION, drawn against TAMORO

TAMORO's letterform facts, which the directions exploit: six letters, three syllables, perfect alternation of consonant/vowel, **two O's and no descenders** — a wordmark-friendly string (compact, symmetric-ish, all-caps-stable). TAMODO shares five of six letters and the same structure; the -kor-class or other fallbacks share none.

### W-A — "Engineered Grotesk" (the evolution of the draft Nick liked) — LEAD

All-caps TAMORO in a bold, tight-tracked geometric grotesk, customized with engineered details: flat-shear terminals on the A and M apexes, and the two O's cut as **slightly squared "supervisor" rounds** (the shape language of an enclosure/hub, not a perfect circle). Monochrome-first (near-black on light, soft-white on dark), zero gradient, zero texture. The bold techno energy of the draft, kept; the scribble/gradient/grid, deleted; survivability per W-6 discipline (monochrome, clearspace, small-size stable).

- **Radio/recognition:** strong; the double-O gives it a visual signature ("the two apertures") that survives tiny favicon sizes.
- **Swap cost:** MODERATE. The system (weight, tracking, terminal language) transfers to any name; the letter-specific cuts re-draw. TAMODO: ~1 letter of rework (R→D), days not weeks. Unrelated fallback: full re-cut of 6–8 letters, ~1–2 weeks of type work.

### W-B — "System Voice" (Inter-derived, cheapest, ships-itself)

The wordmark is TAMORO set in **Inter** (the system's own voice — typography-reference §1) at 700, tracking tightened −2..−3%, with at most ONE ownable modification (REC: a single horizontal spur deleted from the R, or the O's swapped for the squared-round from W-A). This is the W-6 HomeSynapse playbook (wordmark = the system font, typeset to spec) applied to the new name.

- **Radio/recognition:** adequate, not distinctive; leans on color/lockup discipline for memorability. Honest read: this is the *floor*, chosen for integrity (the product IS its type system) and speed.
- **Swap cost:** NEAR-ZERO. Any name re-renders from the token in an afternoon. This direction is the rename-readiness limit case — and therefore the correct **interim mark** for anything needed between now and G-2 (internal decks, counsel exhibits), because it presumes nothing.

### W-C — "Rounded Techno-Humanist" (the warm counterweight)

Title-case **Tamoro** in a semi-geometric rounded sans (custom-drawn or heavily modified), moderate weight (650-class), generous counters; the warmth register the -kor exploration was chasing, carried by letterforms instead of a different name. Squared-round O's again as the connective shape language.

- **Radio/recognition:** warmest and most consumer; risks under-shooting the infrastructure gravitas (the Framework-counterweight taken slightly too far). Best held as the future consumer-edition register rather than the launch mark.
- **Swap cost:** HIGH. Fully custom letterforms; a name swap is a full re-draw (~2+ weeks).

**Lane REC:** develop **W-A as the lead** with **W-B as the standing interim + fallback**. W-A honors Nick's recorded taste while fixing every critiqued element; W-B guarantees the program is never blocked on type work. (Consistent with the standard-characters ruling: no wordmark files with the first application regardless.)

## 2. Device-mark directions (single device, per Nick) — EXPLORATION

Design observation of record (not clearance): the filled-red-circle field is crowded in exactly our aisle, and the rising-sun echo is on-brand for a "tomorrow" name but must be handled deliberately (a red disc + horizon reads national-flag before it reads dawn). The three directions below each escape the crowd differently; all are drawn to the same laws: **single device · monochrome-survivable · accent applied as a controlled secondary (visual-design-reference §6.3) · governed usage rules ship with it day one (W-3a #2, the Oracle "O"-tag model) · never conveys state by color alone.**

### D-A — "First Light" (the horizon arc) — LEAD for the tomorrow-evocation

A single **open arc rising over a horizontal baseline** — dawn reduced to two strokes. Not a filled disc (escapes the red-circle crowd and mutes the flag echo), not a full sun (no radiating spokes). Reads: tomorrow / the day arriving / calm. Stroke-drawn, so it inherits any color discipline; at favicon scale it survives as "the arc." Secondary read, deliberate: the arc-over-line is also a **signal rising above a threshold** — the confirmation moment — which ties the tomorrow story to the honesty story in one figure.
- **Name-dependence: NONE** (survives any name whose story tolerates "tomorrow/dawn" — and per the brand criterion, any ratified name will). Swap cost: zero.

### D-B — "The Receipt" (confirmation tick-node) — the differentiator made geometric

A checkmark whose two strokes terminate in a **node/dot** — the causal-chain vertex fused with the confirm gesture: *verified, with receipts*. Fully name-agnostic and fully thesis-agnostic-proof: it renders never-false-CONFIRMED as a figure. Risk, stated honestly: check-based marks are their own crowded design field (a design observation), so distinctiveness must come from the node-terminal execution and the system around it.
- **Name-dependence: NONE.** Swap cost: zero.

### D-C — "Aperture T" (letter-bound monogram)

A negative-space **T** inside a squared-round aperture (the W-A O-shape as the container) — app-icon-native, tight, techno. The strongest single-device lockup with the W-A wordmark.
- **Name-dependence: INITIAL-BOUND.** Survives TAMORO→TAMODO free (both T); any non-T fallback is a full re-draw. Swap cost: zero-or-total, nothing between.

**Lane REC:** carry **D-A and D-B into the post-G-2 logo session as the pair to prototype** (one carries the name's story, one carries the product's), with D-C as the app-icon variant IF the T survives G-2. Do not spend beyond paper before G-2 (the ruled hold).

## 3. Color system — accessibility-CHECKED, light/dark, name-agnostic (survives any name)

Base: the locked neutrals stand (Obsidian Graphite `#0B0F14` · Carbon Slate `#151B23` · Mineral Ash `#ECEFF3` — visual-design-reference §2). Dark is the recorded brand default; light is first-class (Nick's 2026-06-27 ruling). The brand accent stays a **cool blue with the interaction monopoly** (W-9; one accent per screen; semantic colors carry state, never decoration; the honest-amber of `UNCONFIRMED` must never be crowded by a warm brand accent — this is a hard argument AGAINST importing the draft logo's red into the UI system: red belongs to the error/severity register).

**Computed this session (WCAG 2.x relative-luminance contrast, exact hexes as documented):**

| Pair (documented palette) | Ratio | AA verdict |
|---|---|---|
| Accent `#3FA6C9` on Obsidian `#0B0F14` | 6.87:1 | PASS normal text |
| Accent `#3FA6C9` on Carbon Slate `#151B23` | 6.19:1 | PASS normal text |
| **Accent `#3FA6C9` on Mineral Ash `#ECEFF3`** | **2.42:1** | **FAIL (below 3:1)** |
| Amber `#C7A14A` on Obsidian | 7.89:1 | PASS normal text |
| **Amber `#C7A14A` on Mineral Ash** | **2.11:1** | **FAIL** |
| Error `#B85E5E` on Obsidian | 4.39:1 | PASS large/UI only (≥3:1), NOT normal text |
| Error `#B85E5E` on Mineral Ash | 3.79:1 | PASS large/UI only |

**The finding (real, and fixable at token level):** the documented palette is dark-optimized; the accent and two of three semantic colors FAIL as text/meaning-carriers on the light background. Light mode therefore requires **mode-paired tokens** — same hue identity, darkened for light surfaces. Structural rules carried forward unchanged: no pure black/white; state = color + shape + text, never color alone; warm illustration palette (W-9 clay/ochre/sage-teal class) illustration-ONLY; brand moments rare (W-10). **Naming note:** every token above is deliberately brand-word-free (`--accent`, not `--tamoro-blue`) — the color system is 100% name-swap-proof by construction.

### 3a. THE ALL-USERS COLOR MANDATE (Nick, 2026-07-23 — standing, verbatim-class)

> "It is still up to us to make the color work for all users, consumers, enterprises, or any other potential customers in the long-term future."

Folded as binding design law on all color work, current and future:

1. **WCAG AA in both modes is the FLOOR, not the target** — the §3 mode-paired tokens implement the floor; token-authoring should prefer AAA where it costs nothing.
2. **Color-vision-deficiency safety is a named check, not an assumption.** The state triad (ok/warn/error) must remain distinguishable under deuteranopia/protanopia/tritanopia simulation at token-authoring time. The existing state-never-by-color-alone law (shape + label always present) is the structural guarantee; the CVD check additionally verifies the hues carry *luminance* separation so color still helps rather than merely not-hurting. Add to the token-authoring session's checklist alongside the §3 contrast table.
3. **The maturation arc applies to color** (W-3a restated for palette): nothing in the palette may encode "hobbyist" or read as consumer-only; the same tokens must serve dashboards on a wall, enterprise/multi-site consoles, and documentation without a re-theme. The neutral-substrate + one-accent + semantic-state model already has this property — the mandate makes it a test: *any proposed color addition must state which customer class it serves and which it risks alienating.*
4. **Future data-visualization palettes** (energy dashboards, history views) inherit the mandate day one: categorical/sequential ramps get the same AA + CVD validation before first use — no chart color enters the system unvalidated.

## 4. Type direction — name-agnostic (survives any name)
