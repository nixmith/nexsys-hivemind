# The Conditions-to-Copy Translation Pass (Branch B - conditional clear)

**What this is:** if the Pelton read comes back **clear WITH CONDITIONS** (the likeliest real-world shape of a graded risk assessment: a narrowed goods/services ID, a class split, a descriptor caution, an adjacent-field warning), each condition must become exactly ONE copy rule appended to the DO-NOT-SAY list. **The output is not legal analysis - it is a diff against the DO-NOT-SAY list (L-C D-2.6).** Where a condition's copy consequence is unclear, it becomes a numbered question on the merged D-4 counsel packet - NEVER an interpretation.

## Step 0 - Capture (Nick, day 0, ~15 min)

Capture EVERY condition, qualification, and caution in the ruling **VERBATIM** - paraphrasing counsel's qualifications is how a condition silently becomes a marketing claim. File the verbatim capture at `context/strategy/counsel-package/<date>_pelton-ruling_conditions_verbatim.md` before any translation begins. The verbatim capture IS the artifact; this table consumes it.

## Step 1 - Translate (hub drafts, Nick reviews; ~2 h)

One row per condition. The worked mappings below are the four condition classes L-C identified; anything that does not fit a class goes straight to the D-4 column.

| # | Counsel's condition (VERBATIM, quoted from the Step-0 capture) | Class | The ONE copy rule it implies | DO-NOT-SAY diff row (appended to D-2.6) | Unclear? -> D-4 question # |
|---|---|---|---|---|---|
| 1 | *(quote)* | | | | |
| 2 | *(quote)* | | | | |

**The four worked class mappings (from L-C D-1.3, adjudication-verified):**

- **Narrowed goods/services ID** -> *"do not describe the product as X on any public surface"* (X = whatever the narrowing excludes).
- **Crowded adjacent field** -> *"no comparative construction against that field"* (no better-than, no instead-of, no migration-from copy naming it).
- **Descriptor caution** -> the descriptor becomes a **banned word** row, verbatim.
- **Class split (clear in one class, crowded in another)** -> a **surface-scoped** rule: the copy rule binds only the surfaces that touch the crowded class (e.g. app-store/service descriptions), stated explicitly per surface.

**Rules of the pass:** one condition -> one rule (a condition that seems to need two rules is two conditions - split the row). No rule may soften, gloss, or narrow the verbatim condition. Any ambiguity goes to the D-4 packet as a question, never resolved here.

## Step 2 - Bind (hub, same day)

Append the diff rows to the DO-NOT-SAY list of record. The amended list is **binding on every downstream surface** (README, announcement, position paper, taglines, handles' one-line parks - everything in the presence stack).

## Step 3 - Re-run AFTER (hub, same week)

Re-run the claim-rails pass **after** the amendment, not before - the amended list is the one that binds (L-C's ordering law, verbatim honored).
